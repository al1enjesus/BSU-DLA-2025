## Ответы на вопросы

### Базовые понятия:
1. **Модуль ядра** - это часть кода, который можно динамически загружать в ядро для добавления функциональности (драйверы, файловые системы и т.д.)
2. **Kernel-space** - привилегированный режим с полным доступом к системе, **user-space** - ограниченный режим для обычных программ
3. **Обращение к NULL указателю** в модуле вызовет kernel panic и крах системы
4. **printf()** нельзя использовать потому что в ядре нет стандартной библиотеки C, вместо этого используется **printk()**
5. **Kernel panic** - критическая ошибка ядра, чтобы избежать нужно проверять указатели и границы массивов

### Жизненный цикл модуля:
6. При **insmod** вызывается `module_init()`, при **rmmod** - `module_exit()`
7. `module_exit()` должна освобождать все ресурсы, выделенные в `module_init()`
8. Если `module_init()` возвращает ошибку, модуль не загружается и `module_exit()` не вызывается
9. **Нельзя** выгрузить модуль если он используется процессами или другими модулями

### Логирование и отладка:
10. **printk()** выводит в kernel log, **printf()** - в stdout; printk имеет уровни важности
11. Уровни: EMERG, ALERT, CRIT, ERR, WARNING, NOTICE, INFO, DEBUG
12. Логи модуля смотрят через `dmesg` или `/var/log/kern.log`
13. **"Tainted kernel"** - ядро помечено как "испорченное" из-за загрузки проприетарных модулей

### Память:
14. **kmalloc()** выделяет физически непрерывную память в ядре, **malloc()** - виртуальную в user-space
15. **Флаги GFP** определяют условия выделения памяти (GFP_KERNEL - может спать, GFP_ATOMIC - не может)
16. Если не освободить память в `module_exit()` будет **утечка памяти** в ядре
17. User-space указатели недействительны в ядре, нужны функции копирования

### Взаимодействие с user-space:
18. **/proc** - виртуальная файловая система для экспорта информации из ядра
19. **/sys** - для атрибутов устройств и конфигурации, более структурирован чем /proc
20. **copy_to_user()** и **copy_from_user()** безопасно копируют данные между пространствами
21. **Character device** - устройство, с которым работают как с файлом (последовательный доступ)

### Параметры и метаданные:
22. Параметры передаются: `sudo insmod module.ko param=value`
23. **MODULE_LICENSE()** нужен для указания лицензии, без GPL некоторые функции недоступны
24. Без лицензии ядро помечается как tainted

### Безопасность:
25. Основные правила: проверять указатели, использовать функции копирования, освобождать ресурсы
26. **Нельзя** использовать бесконечные циклы - могут заблокировать систему
27. В ядре **нет FPU** потому что это замедлило бы переключение контекста
28. При kernel panic в VM нужно перезагрузить и проверить код на ошибки

### Практические вопросы:
29. Загруженные модули смотрят через `lsmod` или `cat /proc/modules`
30. Информацию о модуле получают через `modinfo module.ko`
