## Ход работы

### Задание A: Модуль "Hello, World!"

#### Описание задания

Создать модуль ядра, который:

- При загрузке (`insmod`) выводит в системный журнал сообщение "Hello from Kvetko Matvey module!"  
- При выгрузке (`rmmod`) выводит сообщение "Goodbye from Kvetko Matvey module!"  
- Принимает строковый параметр `message`; если он указан, выводится кастомное сообщение вместо стандартного  

#### Исходный код

`./src/hello_module.c`  

#### Сборка и тестирование

```bash
cd src/
make check
make
sudo insmod ./hello_module.ko          # загрузка без параметра
sudo dmesg | tail -1                    # проверка сообщения
sudo rmmod hello_module                 # выгрузка
sudo insmod ./hello_module.ko message="Custom_Test_Message"  # загрузка с параметром
sudo dmesg | tail -1
sudo rmmod hello_module                 # финальная выгрузка
````

**Ожидаемые сообщения в dmesg:**

* Загрузка без параметра: `Hello from Kvetko Matvey module!`
* Загрузка с параметром: `Custom_Test_Message`
* Выгрузка: `Goodbye from Kvetko Matvey module!`


### Задание B: /proc файл с записью

#### Описание задания

Создать модуль, регистрирующий файл `/proc/my_config` с возможностью:

* Чтения (`cat`) и записи (`echo`)
* Возврата текущего значения при чтении
* Обновления значения при записи
* Значения по умолчанию `"default"`
* Ограничения длины строки: 256 символов

#### Исходный код

`./src/proc_module.c`

#### Сборка и тестирование

```bash
cd src/
make check
make
sudo insmod ./proc_module.ko
ls -l /proc/my_config
cat /proc/my_config                   # чтение по умолчанию
echo "New custom value" > /proc/my_config
cat /proc/my_config                   # проверка обновления
sudo rmmod proc_module
ls -l /proc/my_config                 # файл должен исчезнуть
```

**Ожидаемые результаты:**

* Чтение по умолчанию: `default`
* После записи: `New custom value`
* После выгрузки: файл удален

## Ответы на вопросы

### Базовые понятия

1. **Модуль ядра** — код, динамически загружаемый в ядро для расширения его функциональности.
2. **Kernel-space vs User-space** — привилегированное пространство ядра и ограниченное пространство приложений.
3. Обращение к **NULL указателю** в ядре вызывает kernel panic.
4. **printf() vs printk()** — `printf()` работает в user-space, `printk()` — в kernel-space.
5. **Kernel panic** — критическая ошибка ядра; избежать можно соблюдением правил безопасного программирования.

### Жизненный цикл модуля

6. `module_init()` вызывается при `insmod`, `module_exit()` — при `rmmod`.
7. `module_exit()` освобождает все ресурсы, выделенные в `module_init()`.
8. Если `module_init()` возвращает ошибку, модуль не загружается, `module_exit()` не вызывается.
9. Нельзя выгрузить модуль, если он используется (счетчик использования > 0).

### Логирование и отладка

10. `printk()` поддерживает уровни логирования (`KERN_INFO`, `KERN_ERR`), `printf()` — нет.
11. Основные уровни: `KERN_EMERG` до `KERN_DEBUG`.
12. Просмотр логов: `dmesg`, `journalctl -k`, `/var/log/kern.log`.
13. **Tainted kernel** — ядро загружено с проприетарными/не-GPL модулями или критическими ошибками.

### Память

14. `kmalloc()` выделяет физически непрерывную память в ядре; `malloc()` — виртуальную память user-space.
15. **Флаги GFP** определяют контекст выделения (`GFP_KERNEL`, `GFP_ATOMIC`).
16. Неосвобождение памяти в `module_exit()` ведет к утечкам в ядре.
17. Нельзя использовать user-space указатели напрямую — это небезопасно.

### Взаимодействие с user-space

18. `/proc` — интерфейс ядра для мониторинга и управления через файлы.
19. `/sys` — sysfs, более структурированная файловая система для устройств и драйверов.
20. `copy_to_user()` / `copy_from_user()` — безопасный обмен данными между kernel-space и user-space.
21. **Character device** — символьное устройство, доступное через стандартные файловые операции.

### Параметры и метаданные

22. Параметры передаются через `insmod имя=значение`, объявляются через `module_param()`.
23. `MODULE_LICENSE()` указывает лицензию модуля (важно для использования функций ядра).
24. Отсутствие лицензии помечает ядро как tainted.

### Безопасность

25. Основные правила: проверка ошибок, освобождение ресурсов, использование `copy_to/from_user`, избегание прямого доступа к user-space указателям, избегание длительных операций.
26. Бесконечный цикл в модуле может зависнуть систему.
27. FPU операции не используются в ядре из-за высокой стоимости контекстных переключений.
28. При kernel panic: перезагрузка, анализ логов, исправление модуля, тестирование в VM.

### Практические вопросы

29. Список загруженных модулей: `lsmod` или `cat /proc/modules`.
30. Информация о модуле: `modinfo имя_модуля.ko`.
