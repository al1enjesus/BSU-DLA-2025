## Сборка и установка проекта

1. **Установка необходимых пакетов:**

```bash
sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)
```

2. **Структура проекта:**

```
./
├── README.md
├── REPORT.md
└── src/
    ├── char_device.c
    ├── hello_module.c
    ├── Makefile
    └── proc_module.c
```

3. **Makefile** должен содержать:

```makefile
obj-m := char_device.o
KDIR := /lib/modules/$(shell uname -r)/build
PWD := $(shell pwd)

all:
    make -C $(KDIR) M=$(PWD)/src modules

clean:
    make -C $(KDIR) M=$(PWD)/src clean
```

4. **Сборка модуля:**

```bash
make
```

5. **Установка и загрузка модуля:**

```bash
sudo insmod src/char_device.ko
```

6. **Проверка устройства:**

```bash
ls -l /dev | grep dehtyarev_device
```

7. **Удаление модуля:**

```bash
sudo rmmod char_device
```

8. **Просмотр логов ядра:**

```bash
dmesg | tail -n 20
```

## Ответы на вопросы

### Базовые понятия

1. **Модуль ядра** — это динамически загружаемый кусок кода, который расширяет функциональность ядра Linux без перезагрузки системы.
   Используется для добавления драйверов устройств, файловых систем и новых возможностей ядра.

2. **Kernel-space** — память ядра, недоступная для обычных приложений; **user-space** — пространство, где работают приложения. Доступ из user-space в kernel-space возможен только через системные вызовы.

3. Обращение к `NULL` указателю в модуле вызовет **kernel panic**, т.к. это нарушение памяти ядра.

4. `printf()` нельзя использовать, т.к. он предназначен для user-space. Для ядра используют `printk()`.

5. **Kernel panic** — критическая ошибка ядра, приводящая к остановке системы. Избегается проверкой указателей, корректным выделением памяти, использованием синхронизации.

### Жизненный цикл модуля

6. При `insmod` вызывается `module_init()`, при `rmmod` — `module_exit()`.

7. Функция `module_exit()` освобождает ресурсы модуля (память, устройства, регистрация).

8. Если `module_init()` возвращает ошибку, модуль не загружается, и ядро откатывает изменения.

9. Модуль нельзя выгрузить, если на него есть активные ссылки (используется другим модулем или процессом).

### Логирование и отладка

10. `printk()` выводит сообщения в лог ядра, `printf()` — в stdout user-space.

11. Уровни логирования ядра: `KERN_EMERG`, `KERN_ALERT`, `KERN_CRIT`, `KERN_ERR`, `KERN_WARNING`, `KERN_NOTICE`, `KERN_INFO`, `KERN_DEBUG`.

12. Логи модуля можно посмотреть через `dmesg` или `journalctl -k`.

13. "Tainted kernel" — ядро загружено с модулем несвободной лицензии или с ошибками безопасности.

### Память

14. `kmalloc()` выделяет память в kernel-space; `malloc()` — в user-space.

15. **GFP флаги** (например, `GFP_KERNEL`) указывают условия выделения памяти (критичность, допустимость сна, приоритет).

16. Если не освободить память в `module_exit()`, возникает **утечка памяти в ядре**, которая может вызвать нестабильность.

17. User-space указатели напрямую нельзя использовать, т.к. kernel-space не имеет прямого доступа к памяти процессов.

### Взаимодействие с user-space

18. `/proc` — виртуальная файловая система для получения информации о ядре и процессах.

19. `/sys` (sysfs) — файловая система для управления параметрами устройств и драйверов; отличается структурой и предназначением (больше для конфигурации).

20. `copy_to_user()` и `copy_from_user()` безопасно копируют данные между пространствами ядра и пользователя.

21. **Character device** — устройство, которое работает с потоками байтов (read/write) через `/dev`, поддерживает `ioctl` и mmap.

### Параметры и метаданные

22. Параметры модуля передаются при загрузке через `insmod module.ko param=value`.

23. `MODULE_LICENSE()` указывает лицензию модуля, влияет на права доступа к функциям ядра.

24. Если не указать лицензию, ядро помечает модуль как **tainted**, некоторые функции ядра будут недоступны.

### Безопасность

25. Правила безопасного кода: проверка указателей, освобождение памяти, защита от гонок, отсутствие доступа к user-space напрямую.

26. Бесконечный цикл в модуле может блокировать ядро, нарушая работу системы.

27. FPU операции запрещены в ядре, т.к. контекст FPU не сохраняется при переключении задач ядра.

28. При kernel panic необходимо перезагрузить систему и изучить логи (`dmesg`).

### Практические вопросы

29. Список загруженных модулей: `lsmod`.

30. Информация о модуле (версия, параметры): `modinfo <module_name>`.
