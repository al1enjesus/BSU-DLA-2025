## 🔍 Ответы на вопросы

### Базовые понятия

**1. Что такое модуль ядра и зачем он нужен?**

Модуль ядра — это фрагмент кода, который может быть динамически загружен и выгружен из ядра Linux во время работы системы без перезагрузки. Модули нужны для:
- Добавления функциональности в ядро (драйверы устройств, файловые системы)
- Сокращения размера основного ядра (компактность)
- Гибкости системы (загружаем только нужное)
- Упрощения разработки (не нужно перекомпилировать всё ядро)

**2. Чем отличается kernel-space от user-space?**

| Аспект | User-space | Kernel-space |
|--------|------------|--------------|
| Привилегии | Ограниченные | Полный доступ ко всему |
| Память | Виртуальная, защищенная | Прямой доступ к физической |
| Крах программы | Только эта программа | Kernel panic (вся система) |
| API | Стандартная библиотека C | Kernel API |
| Отладка | Простая (gdb, valgrind) | Сложная (printk, kgdb) |

**3. Что произойдёт, если в модуле обратиться к NULL указателю?**

Произойдет kernel panic (крах системы). В отличие от user-space, где program получает SIGSEGV и завершается, в kernel-space нет защиты памяти, и обращение к NULL указателю приведет к краху всего ядра.

**4. Почему нельзя использовать `printf()` в модуле ядра?**

В модуле ядра нет стандартной библиотеки C. Функция `printf()` недоступна, так как:
- Ядро работает в изолированном пространстве без libc
- Нет понятия stdout/stderr в kernel-space
- Вместо этого используется `printk()` для записи в kernel log buffer

**5. Что такое kernel panic и как его избежать?**

Kernel panic — это аварийная остановка ядра Linux при критической ошибке. Чтобы избежать:
- Всегда проверять возвращаемые значения функций
- Правильно управлять памятью (парные kmalloc/kfree)
- Не обращаться к NULL указателям
- Использовать правильные API для копирования данных user↔kernel
- Тщательно тестировать код в виртуальной машине

### Жизненный цикл модуля

**6. Какие функции вызываются при `insmod` и `rmmod`?**

- **При `insmod`:** вызывается функция, зарегистрированная через `module_init()`
- **При `rmmod`:** вызывается функция, зарегистрированная через `module_exit()`

**7. Что должна делать функция `module_exit()`?**

Функция `module_exit()` должна:
- Освободить ВСЕ ресурсы, выделенные в `module_init()`
- Отменить все регистрации (proc файлы, character devices, etc.)
- Освободить выделенную память (kfree)
- Остановить все запущенные потоки/таймеры
- Вернуть систему в исходное состояние

**8. Что происходит, если `module_init()` возвращает ошибку?**

Если `module_init()` возвращает не-ноль:
- Модуль НЕ загружается в систему
- `module_exit()` НЕ вызывается автоматически
- Ресурсы, выделенные до ошибки, нужно освободить вручную в самой `module_init()`
- `insmod` завершится с ошибкой

**9. Можно ли выгрузить модуль, если он используется?**

Нет! Если модуль используется (счетчик ссылок > 0), команда `rmmod` вернет ошибку:
```
rmmod: ERROR: Module module_name is in use
```
Сначала нужно закрыть все процессы/ресурсы, использующие модуль.

### Логирование и отладка

**10. Чем `printk()` отличается от `printf()`?**

| Аспект | printf() | printk() |
|--------|----------|----------|
| Место работы | User-space | Kernel-space |
| Куда выводит | stdout | Kernel log buffer |
| Где смотреть | Терминал | dmesg, /var/log/kern.log |
| Уровни важности | Нет | Есть (KERN_INFO, KERN_ERR) |
| Блокировка | Может блокироваться | Не блокируется |

**11. Какие уровни логирования существуют в ядре?**

```
KERN_EMERG   (0) - Аварийная ситуация
KERN_ALERT   (1) - Требует немедленных действий  
KERN_CRIT    (2) - Критическая ситуация
KERN_ERR     (3) - Ошибка
KERN_WARNING (4) - Предупреждение
KERN_NOTICE  (5) - Заметка (важное сообщение)
KERN_INFO    (6) - Информация
KERN_DEBUG   (7) - Отладочная информация
```

**12. Как посмотреть логи модуля?**

```bash
dmesg                    # Все сообщения ядра
dmesg | tail -20         # Последние 20 строк
dmesg | grep module_name # Поиск по имени модуля
dmesg -w                 # Живой просмотр
tail -f /var/log/kern.log  # Через файл лога
journalctl -k            # Через systemd журнал
```

**13. Что означает "tainted kernel"?**

"Tainted kernel" — испорченное ядро, которое содержит:
- Модули без GPL лицензии
- Модули, загруженные принудительно (--force)
- Модули из внешних источников (не из ядра)
Такое ядро может работать нестабильно, и сообщения о багах могут быть отклонены разработчиками.

### Память

**14. Чем `kmalloc()` отличается от `malloc()`?**

| Аспект | malloc() | kmalloc() |
|--------|----------|-----------|
| Область | User-space | Kernel-space |
| Память | Виртуальная | Физическая/виртуальная |
| Флаги | Нет | Есть (GFP_KERNEL, GFP_ATOMIC) |
| Контекст | Любой | Зависит от флагов |
| Освобождение | free() | kfree() |
| Размер | Любой | Ограничен (обычно до 128KB) |

**15. Что такое флаги GFP и зачем они нужны?**

GFP (Get Free Pages) флаги указывают, как выделять память:
- **GFP_KERNEL** — можно спать/блокироваться (обычный контекст)
- **GFP_ATOMIC** — нельзя спать (interrupt context)
- **GFP_USER** — для пользователских данных
- **GFP_DMA** — память для DMA операций

**16. Что произойдёт, если не освободить память в `module_exit()`?**

Произойдет утечка памяти (memory leak):
- Память останется выделенной после выгрузки модуля
- Система потеряет доступ к этой памяти навсегда
- При множественных загрузках/выгрузках может закончиться память
- Возможна нестабильность системы

**17. Почему нельзя использовать user-space указатели напрямую в ядре?**

User-space указатели:
- Ссылаются на виртуальную память процесса
- Могут быть невалидными в контексте ядра
- Могут вызвать page fault в kernel mode
- Нарушают изоляцию между user и kernel space

Нужно использовать `copy_from_user()` / `copy_to_user()`.

### Взаимодействие с user-space

**18. Что такое `/proc` и для чего он используется?**

`/proc` — виртуальная файловая система для:
- Экспорта информации из ядра в user-space
- Настройки параметров ядра во время выполнения
- Интерфейса между kernel и пользовательскими программами
- Просмотра состояния процессов и системы

Примеры: `/proc/cpuinfo`, `/proc/meminfo`, `/proc/modules`

**19. Что такое `/sys` (sysfs) и чем отличается от procfs?**

| Аспект | /proc | /sys |
|--------|-------|------|
| Назначение | Процессы + разная информация | Объекты ядра + драйверы |
| Структура | Произвольная | Строго иерархическая |
| Содержимое файла | Многострочное | Одно значение на файл |
| Использование | Информация + настройки | Управление устройствами |

**20. Зачем нужны функции `copy_to_user()` и `copy_from_user()`?**

Эти функции:
- Безопасно копируют данные между kernel и user space
- Проверяют валидность пользовательских указателей  
- Обрабатывают page faults корректно
- Предотвращают kernel panic от невалидных адресов
- Обеспечивают изоляцию между пространствами

**21. Что такое character device и как он работает?**

Character device — устройство, которое:
- Передает данные по одному символу (байту)
- Поддерживает операции: open, close, read, write
- Регистрируется в системе с major/minor номерами
- Создает файл в `/dev/` для доступа из user-space
- Примеры: `/dev/null`, `/dev/random`, `/dev/tty`
