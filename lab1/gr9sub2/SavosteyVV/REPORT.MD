## Задание A (Частотный анализ слов в syslog (TOP‑5))

Так как использую Debian , который является systemd-based ОС , где традиционный syslog заменен Journal, сдампил логи с журнала в файл src/syslog.

```bash
    journalctl -n 10000 > syslog
```

Команда:
 
   ```bash
    cat syslog \
  | cut -d: -f4- \
  | tr -cs '[:alnum:]' '\n' \
  | tr '[:upper:]' '[:lower:]' \
  | grep -vE "^[0-9]+$" \
  | sort \
  | uniq -c \
  | sort -nr \
  | head -n 5
```

**Детальный разбор конвейера:**

1.  `cat syslog`: Читает содержимое файла и передает его в стандартный вывод (stdout).
2.  `cut -d: -f4-`:
    *   `-d:` (delimiter) — использует двоеточие как разделитель полей.
    *   `-f4-` (fields) — вырезает всё, начиная с 4-го поля и до конца строки.
    *   *Зачем:* Вывод `journalctl` содержит метку времени и имя хоста (например, `Dec 04 19:00:00 kali ...`). Чтобы слова "Dec", "kali" или цифры времени не попадали в топ статистики, мы отрезаем метаданные, оставляя только тело сообщения и процесс.
3.  `tr -cs '[:alnum:]' '\n'`: 
    *   `-c` (complement) — берет всё, что не является буквой или цифрой (`[:alnum:]`).
    *   `-s` (squeeze) — сжимает повторяющиеся символы в один.
    *   `'\n'` — заменяет найденные символы (пробелы, скобки, знаки препинания) на перевод строки.
    *   *Результат:* Каждое слово оказывается на новой строке.
4.  `tr '[:upper:]' '[:lower:]'`: Нормализация регистра. Переводит все символы в нижний регистр, чтобы `Error` и `error` считались одним словом.
5.  `grep -vE "^[0-9]+$"`: Фильтрация шума.
    *   `-v` (invert match) — исключает строки, соответствующие шаблону.
    *   `-E` (extended regex) — включает расширенные регулярные выражения.
    *   `^[0-9]+$` — шаблон чистого числа (от начала `^` до конца `$` строки только цифры). Убирает PID процессов, порты и значения времени.
6.  `sort`: Сортирует слова по алфавиту. Это обязательно перед использованием `uniq`.
7.  `uniq -c`: Агрегация. Схлопывает идущие подряд одинаковые строки и добавляет в начало количество их повторений (count).
8.  `sort -nr`: Финальная сортировка.
    *   `-n` (numeric) — сортирует как числа , а не как текст.
    *   `-r` (reverse) — от большего к меньшему (по убыванию частоты).
9.  `head -n 5`: Выводит только первые 5 строк (TOP-5).

**Вывод**

```text
   1735 service
   1635 of
   1486 to
   1476 message
   1342 from
```

**Анализ результата:**
*   **Столбец 1:** Количество вхождений слова.
*   **Столбец 2:** Само слово.


## Задание Б (Неудачные попытки входа (auth.log))

Так как не было каких-либо попыток подключения к системе, файл auth.log было решено сгенерировать , в соответствии с его форматом. В этом помог LLM, который предоставил такой скрипт(gen_auth.sh):
```bash
#!/bin/bash

# Файл куда пишем
OUTPUT="auth.log"

# Очистим файл если был
> "$OUTPUT"

# Массивы данных для рандомизации
USERS=("root" "admin" "kali" "support" "user" "oracle")
IPS=("192.168.1.55" "10.0.0.13" "45.33.22.11" "192.168.1.55" "192.168.1.55" "172.16.0.5")
# Генерируем 200 записей
for i in {1..200}; do
    USER=${USERS[$RANDOM % ${#USERS[@]}]}
    IP=${IPS[$RANDOM % ${#IPS[@]}]}
    PORT=$((10000 + RANDOM % 50000))
    TIME=$(date "+%b %d %H:%M:%S")

    # 80% Failed password, 20% Invalid user
    if [ $((RANDOM % 5)) -eq 0 ]; then
         echo "$TIME kali sshd[1337]: Failed password for invalid user $USER from $IP port $PORT ssh2" >> "$OUTPUT"
    else
         echo "$TIME kali sshd[1337]: Failed password for $USER from $IP port $PORT ssh2" >> "$OUTPUT"
    fi
done

```

**Команда:**
```bash
grep -E 'Failed|Invalid' auth.log \
  | grep -oE '[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}' \
  | sed -E 's/([0-9]+\.[0-9]+\.[0-9]+\.)[0-9]+/\1x/g' \
  | sort \
  | uniq -c \
  | sort -nr \
  | head -n 10
```

**Детальный разбор конвейера:**

1.  `grep -E 'Failed|Invalid' auth.log`: **Первичная фильтрация**.
    *   Ищет строки, содержащие ключевые индикаторы неудачного входа: `Failed` (неверный пароль) или `Invalid` (попытка входа под несуществующим пользователем).
2.  `grep -oE '[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}'`: **Экстракция сущностей**.
    *   `-o` (only-matching): Выводит не всю строку лога, а **только** ту часть, которая совпала с шаблоном.
    *   Шаблон соответствует структуре IPv4: четыре группы цифр (от 1 до 3 знаков), разделенные точками.
    *   *Результат:* Поток текстовых строк лога превращается в список IP-адресов.
3.  `sed -E 's/([0-9]+\.[0-9]+\.[0-9]+\.)[0-9]+/\1x/g'`: **Санитизация данных (Masking)**.
    *   Используется потоковый редактор `sed` с регулярным выражением.
    *   `(...)`: Группа захвата (Capture Group). Она "запоминает" первые три октета и точку (например, `192.168.1.`).
    *   `[0-9]+`: Соответствует четвертому октету, который мы хотим скрыть (не входит в скобки, значит, не запоминается).
    *   `\1x`: Заменяет всё найденное на содержимое первой группы (`\1`) + символ `x`.
    *   *Итог:* `192.168.1.55` превращается в `192.168.1.x`.
4.  `sort`: Сортировка IP-адресов. Необходима для корректной работы `uniq`.
5.  `uniq -c`: Подсчет количества попыток входа с каждого (уже замаскированного) IP-адреса.
6.  `sort -nr`: Ранжирование списка по количеству атак (от большего к меньшему).
7.  `head -n 10`: Вывод топ-10 атакующих подсетей.

**Формат вывода и анализ:**

Пример полученного вывода(так как скрипт генерирует случайные вариации попыток входа):
```text
     98 192.168.1.x
     42 45.33.22.x
     32 172.16.0.x
     28 10.0.0.x
```

*   **1-й столбец:** Количество зафиксированных неудачных попыток (число событий).
*   **2-й столбец:** Замаскированный IP-адрес источника (Source IP).
Вот готовый блок для **Задания В**. Он завершает техническую часть анализа.

В этом задании акцент делается на **Аудите системы (System Audit)**. Для специалиста по ИБ важно уметь отслеживать, что устанавливалось в системе, чтобы выявить появление "теневого ИТ" (Shadow IT), хакерских утилит, которые не должны быть на сервере, или проверить, обновлялись ли критически важные библиотеки.

## Задание В (Установки пакетов (dpkg.log))

**Команда:**
```bash
grep ' install ' /var/log/dpkg.log \
  | awk '{print $4}' \
  | cut -d: -f1 \
  | sort \
  | uniq -c \
  | sort -nr \
  | head -n 10
```

**Детальный разбор конвейера :**

1.  `grep ' install ' /var/log/dpkg.log`: **Фильтрация событий**.
    *   Мы ищем строки, содержащие слово `install`, отбитое пробелами. Это позволяет найти именно *действия* по установке, отсекая строки статусов вида `half-installed` или `pre-installation`.
2.  `awk '{print $4}'`: **Извлечение поля**.
    *   Утилита `awk` разбивает строку по пробелам. В формате лога `dpkg` (например: `2023-12-04 10:00:01 install libc6:amd64 ...`) имя пакета обычно находится в 4-м столбце.
3.  `cut -d: -f1`: **Очистка данных**.
    *   Имена пакетов записываются как `package_name:architecture` (например, `openssl:amd64`).
    *   `cut` обрезает всё, начиная с двоеточия, чтобы `openssl` и `openssl:amd64` считались одной сущностью для статистики.
4.  `sort`: Подготовка списка к агрегации (группирует одинаковые строки вместе).
5.  `uniq -c`: **Агрегация**. Подсчитывает количество установок/обновлений для каждого пакета.
6.  `sort -nr`: **Ранжирование**. Сортирует список по частоте (числу) в обратном порядке.
7.  `head -n 10`: Вывод топ-10 пакетов.

**Формат вывода и анализ:**

Пример вывода:
```text
      1 strace
      1 ltrace
      1 libsource-highlight-common
      1 libsource-highlight4t64
      1 libpython3.13-stdlib
      1 libpython3.13-minimal
      1 libpython3.13
      1 libipt2
      1 libdebuginfod-common
      1 libdebuginfod1t64

```

*   **1-й столбец:** Количество событий установки (включая обновления версий).
*   **2-й столбец:** Имя пакета.
