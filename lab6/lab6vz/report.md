## 2. Теория

### Что такое VFS и зачем нужен FUSE

**VFS (Virtual File System)** — это прослойка в ядре Linux, которая делает так, чтобы приложения могли работать с любыми файловыми системами через одинаковый набор функций. VFS оперирует понятиями вроде `inode` (информация о файле), `dentry` (запись в директории), `file` (открытый файл) и `superblock` (информация о всей ФС).

**FUSE (Filesystem in Userspace)** позволяет писать файловые системы как обычные программы, которые работают в пространстве пользователя. В ядре есть небольшой модуль, который перенаправляет запросы от VFS в пользовательский процесс. Это намного проще и безопаснее, чем писать код для ядра, хотя и немного медленнее из-за переключений между режимами работы процессора.

### Как это работает

```
┌────────────┐
│  Программа │
└──────┬─────┘
       │ системные вызовы (open, read, write...)
       ▼
┌────────────┐
│    VFS     │
└──────┬─────┘
       │ общий интерфейс ФС
       ▼
┌─────────────────┐
│ Модуль FUSE     │
│ в ядре          │
└──────┬──────────┘
       │ протокол FUSE
       ▼
┌─────────────────┐
│ Наша программа  │  ← myfuse
│ (userspace)     │
└─────────────────┘
```

### Реализованные операции

Я реализовал следующие операции для работы с файлами:
- `getattr` — получение информации о файле (аналог команды `stat`)
- `readdir` — чтение списка файлов в директории
- `open` — открытие файла (проверка прав доступа)
- `read` — чтение данных из файла
- `write` — запись данных в файл
- `create` — создание нового файла
- `unlink` — удаление файла
- `mkdir` — создание директории
- `rmdir` — удаление директории
- `destroy` — очистка ресурсов при размонтировании

Для режима `rot13` добавлено шифрование/дешифрование при записи и чтении, для `upper` — преобразование в заглавные буквы при чтении. Все операции логируются в stderr с отметкой времени.

## 3. Выполнение работы

### Организация кода

Написал единую программу `myfuse`, которая может работать в трёх режимах. Режим выбирается через параметр `--mode=<passthrough|rot13|upper>`, по умолчанию используется `passthrough`. Первым аргументом передаётся исходная директория, вторым — точка монтирования.

Структура файлов:
```
src/
├── myfuse.c        # главная функция, парсинг аргументов
├── operations.c    # все операции FUSE
├── operations.h    # заголовочный файл
└── utils.c         # вспомогательные функции (логирование, ROT13, upper)
```

Важные моменты реализации:
- Функция `normalize_join` безопасно строит полный путь и защищает от выхода за пределы базовой директории через `..`
- Каждая операция логируется с временной меткой
- При ошибках возвращается `-errno`
- Трансформации данных:
  - В режиме `rot13` данные шифруются перед записью и расшифровываются при чтении
  - В режиме `upper` данные преобразуются в верхний регистр только при чтении

### Задание A: Простая зеркальная ФС

#### Как реализовал

Режим passthrough просто перенаправляет все операции на реальную файловую систему. Для каждой операции формируется полный путь (базовая директория + относительный путь) и выполняется соответствующий системный вызов:
- `fs_getattr` использует `lstat()` для получения информации о файле
- `fs_readdir` открывает директорию через `opendir()`, читает содержимое через `readdir()` и заполняет буфер
- `fs_open` проверяет доступ через `open()`
- `fs_read` и `fs_write` используют `pread()` и `pwrite()` для работы с данными
- `fs_create`, `fs_unlink`, `fs_mkdir`, `fs_rmdir` — стандартные вызовы libc

#### Запуск

```bash
make
mkdir -p /tmp/source /mnt/fuse
./myfuse /tmp/source /mnt/fuse -f
```

#### Проверка работы

### Задание B: ФС с шифрованием ROT13

#### Реализация

Алгоритм ROT13 сдвигает каждую букву латинского алфавита на 13 позиций (A→N, B→O и т.д.). Интересная особенность — двойное применение ROT13 возвращает исходный текст.

* При записи (`write`) входящие данные копируются во временный буфер, преобразуются через ROT13 и записываются на диск в зашифрованном виде
* При чтении (`read`) данные читаются с диска в зашифрованном виде, затем применяется ROT13 для расшифровки и возвращаются пользователю
* Метаданные файлов (имена, права, даты) не изменяются

#### Запуск

```bash
make
mkdir -p /tmp/source /mnt/fuse
./myfuse /tmp/source /mnt/fuse -f --mode=rot13
```

#### Тестирование

```bash
# Записываем через точку монтирования
$ echo "Hello World" > /mnt/fuse/secret.txt
[2025-11-21 05:29:30] CREATE: /secret.txt (result: 0)
[2025-11-21 05:29:30] GETATTR: /secret.txt (result: 0)
[2025-11-21 05:29:30] WRITE: /secret.txt (result: 12)

# Смотрим на реальный файл — он зашифрован
$ cat /tmp/source/secret.txt
Uryyb Jbeyq

# Читаем через FUSE — получаем расшифрованный текст
$ cat /mnt/fuse/secret.txt
[2025-11-21 05:30:04] OPEN: /secret.txt (result: 0)
[2025-11-21 05:30:04] READ: /secret.txt (result: 12)
Hello World
```

## 4. Тестирование производительности

### Методика тестирования

Сравнивал две конфигурации: **FUSE** (моя файловая система) и **ext4** (обычная директория на ext4).

* **Latency** — задержка на операциях с небольшими объёмами данных. Каждая операция повторяется много раз и вычисляется среднее время.
* **Throughput** — пропускная способность для больших файлов (1MB, 10MB, 100MB). Измеряется время записи/чтения и вычисляется скорость в MB/s.
* **IOPS** — количество операций в секунду. Создаётся и удаляется 1000 мелких файлов (~1KB каждый).

Результаты сохраняются в CSV файл, который потом обрабатывается скриптом `ascii_graph.py` для построения графиков.

#### Тест 1: Задержка операций

Измерял время выполнения базовых операций (`open`, `getattr`, `read` 4KB, `write` 4KB):

* `open` — через bash встроенную команду `exec`:
  ```bash
  bash -c 'exec 3<"/path/to/file"; exec 3>&-'
  ```
  Выполнял это в цикле и усреднял результаты.

* `getattr` (stat) — использовал функцию `measure_ms_repeated`:
  ```bash
  avg_ms=$(measure_ms_repeated 100 stat -c "%s" "/path/to/file")
  ```
  Команда `stat` запускается 100 раз подряд, функция возвращает среднее время.

* `read 4KB` и `write 4KB` — замеры через `dd`:
  ```bash
  dd if="$file" bs=4096 count=1 of=/dev/null
  dd if=/dev/zero of="$tmp" bs=4096 count=1
  ```

#### Тест 2: Пропускная способность

Последовательное чтение и запись файлов разного размера:

```bash
dd if=/dev/zero of="$out" bs=1M count=$size_mb oflag=direct
dd if="$out" of=/dev/null bs=1M iflag=direct
```

#### Тест 3: Операции с мелкими файлами

Создание и удаление 1000 файлов по 1KB:

```bash
sh -c 'for i in $(seq 1 1000); do echo x > /mnt/fuse/f$i; done'
sh -c 'for i in $(seq 1 1000); do rm /mnt/fuse/f$i; done'
```

## 5. Ответы на вопросы

### Архитектура файловых систем

1. **Что такое VFS и для чего она используется?**
   VFS — это слой абстракции в ядре Linux, который обеспечивает единый интерфейс для работы с разными типами файловых систем. Благодаря VFS приложения могут использовать одинаковые системные вызовы независимо от того, на какой файловой системе они работают.

2. **В чём разница между inode, dentry и file descriptor?**
   * `inode` — структура данных, хранящая метаинформацию о файле: размер, права доступа, указатели на блоки данных
   * `dentry` — запись в кеше директорий, связывает имя файла с его inode и ускоряет поиск по пути
   * `file descriptor` — числовой идентификатор открытого файла в процессе, содержит текущую позицию чтения/записи и флаги открытия

3. **Что содержит структура `struct inode`?**
   В inode хранятся метаданные файла: размер, режим доступа (права), владелец (UID) и группа (GID), временные метки доступа и модификации, количество жёстких ссылок, указатели на блоки данных.

4. **Что такое superblock и какие данные в нём хранятся?**
   Superblock — это метаданные всей файловой системы: тип ФС, размер блока, общее количество блоков и inode, количество свободных блоков, параметры монтирования.

5. **Как работает кеш dentry и зачем он нужен?**
   Кеш dentry хранит соответствия между именами файлов и их inode в памяти. Это позволяет быстро находить файлы по пути без обращения к диску при каждом вызове `open()` или `stat()`.

### FUSE

6. **Как FUSE взаимодействует с ядром?**
   В ядре есть модуль FUSE, который получает запросы от VFS и передаёт их в пользовательский процесс через специальное устройство `/dev/fuse`. Процесс обрабатывает запрос и возвращает результат обратно в ядро, которое передаёт его приложению.

7. **Опишите путь системного вызова `read()` для FUSE.**
   Приложение вызывает `read()` → VFS определяет, что это FUSE файловая система → ядро формирует запрос и отправляет его через `/dev/fuse` в пользовательский процесс → процесс читает данные (из реального файла или генерирует их) и отправляет ответ в ядро → ядро возвращает данные приложению.

8. **Почему FUSE медленнее встроенных в ядро файловых систем?**
   Из-за дополнительных переключений между режимами процессора (kernel mode ↔ user mode), копирования данных между пространствами, синхронизации. Каждая операция требует больше времени, чем прямой вызов функции в ядре.

9. **Какие плюсы даёт разработка ФС в userspace?**
   Проще разрабатывать и отлаживать, безопаснее (ошибка не приведёт к крашу ядра), можно использовать обычные библиотеки и инструменты разработки, быстрее цикл итераций.

10. **Примеры популярных FUSE файловых систем.**
    sshfs (доступ к удалённым файлам по SSH), ntfs-3g (поддержка NTFS), rclone (облачные хранилища), encfs (шифрование), gcsfuse (Google Cloud Storage).

### Операции с файлами

11. **Что делает операция `getattr()` и когда она вызывается?**
    Возвращает атрибуты файла — размер, права, временные метки. Вызывается при команде `stat`, `ls`, перед многими другими операциями для проверки существования и прав доступа.

12. **Разница между `open()` и `create()`?**
    `open()` открывает существующий файл и проверяет права доступа. `create()` создаёт новый файл и сразу открывает его (эквивалент `open()` с флагом O_CREAT).

13. **Зачем `read()` принимает параметр `offset`?**
    Чтобы можно было читать файл с произвольной позиции, не изменяя текущую позицию в файловом дескрипторе. Это важно для параллельного чтения и для операций типа `pread()`.

14. **Как `readdir()` возвращает список файлов?**
    В FUSE используется callback-функция `filler()`: для каждого файла в директории вызывается `filler(buf, name, stat, offset, flags)`, которая добавляет запись в буфер результата.

15. **Что должна возвращать `getattr()` для директории?**
    Структуру stat с типом S_IFDIR, правами доступа (обычно rwx для владельца), количеством жёстких ссылок (минимум 2: сама директория и `.`), временными метками.

### Метаданные и атрибуты

16. **Что такое атрибуты файла?**
    Это метаданные: размер файла, права доступа (rwx), владелец и группа, временные метки (время создания, модификации, доступа), тип файла (обычный, директория, ссылка), количество жёстких ссылок.

17. **Что означают биты прав доступа?**
    Формат rwxrwxrwx: первая тройка — права владельца, вторая — группы, третья — остальных пользователей. r (read) — чтение, w (write) — запись, x (execute) — выполнение.

18. **Разница между mtime, atime и ctime?**
    * `atime` — время последнего чтения файла
    * `mtime` — время последнего изменения содержимого
    * `ctime` — время последнего изменения метаданных inode (прав, владельца и т.д.)

19. **Разница между hard link и symbolic link?**
    * Hard link — ещё одно имя для того же inode, работает только в пределах одной ФС, файл удаляется только когда счётчик ссылок достигает нуля
    * Symbolic link — отдельный файл, содержащий путь к другому файлу, может указывать куда угодно (даже на несуществующий файл), работает между разными ФС

20. **Как ФС определяет размер файла?**
    Размер хранится в поле `i_size` структуры inode. При чтении за пределами этого размера возвращается EOF (конец файла).

### Физическая организация

21. **Что такое блок в файловой системе?**
    Минимальная единица выделения дискового пространства, обычно 4KB. Файловая система работает с данными блоками — даже маленький файл занимает минимум один блок.

22. **Принцип непрерывного размещения файлов.**
    Файлу выделяется последовательная область блоков на диске. Плюс — быстрый последовательный доступ. Минусы — фрагментация, сложность увеличения размера файла.

23. **Как работает организация через связанный список блоков?**
    Каждый блок содержит указатель на следующий блок файла. Удобно для динамического роста, но медленный произвольный доступ — нужно пройти по всей цепочке.

24. **Что такое inode-based allocation?**
    Inode содержит массив указателей на блоки данных файла (прямые, одноуровневые косвенные, двухуровневые и т.д.). Комбинирует быстрый произвольный доступ и гибкое выделение памяти.

25. **Сравните ext4 и btrfs.**
    * ext4 — классическая журналируемая ФС на основе inode, стабильная и быстрая, проверенная временем
    * btrfs — современная copy-on-write ФС с поддержкой снимков, подтомов, контрольных сумм, более гибкая но сложнее

### Производительность

26. **Почему большие файлы читаются быстрее множества мелких?**
    Последовательное чтение позволяет использовать read-ahead (упреждающее чтение), меньше системных вызовов на единицу данных, меньше переключений контекста, диск работает эффективнее без частых seek операций.

27. **Что такое read-ahead?**
    Механизм упреждающего чтения: когда ФС видит последовательное чтение, она автоматически загружает в память следующие блоки заранее. Это снижает задержки и улучшает производительность.

28. **Как page cache ускоряет доступ?**
    Page cache хранит в оперативной памяти недавно использованные страницы файлов. Повторное чтение данных происходит из RAM без обращения к диску, что намного быстрее.

29. **Почему SSD быстрее HDD?**
    У SSD нет механических частей — нет времени на перемещение головки и вращение диска. Меньше задержки, выше IOPS, особенно для произвольного доступа.

30. **Что влияет на производительность FUSE?**
    Частота мелких операций (каждая требует переключения контекста), накладные расходы на IPC, качество реализации userspace процесса, использование кеширования, настройки ядра (page cache), характеристики диска.

## 6. Заключение

В ходе работы я изучил архитектуру виртуальной файловой системы Linux и освоил практические навыки создания пользовательских файловых систем через FUSE.

Реализовал три варианта файловых систем:
* passthrough — простое зеркалирование, все операции проксируются на реальную ФС
* rot13 — прозрачное шифрование/дешифрование содержимого файлов
* upper — преобразование текста в верхний регистр при чтении

Тестирование показало, что FUSE добавляет заметные накладные расходы, особенно на мелких операциях (создание/удаление файлов, stat). Для больших последовательных операций с файлами размером 1MB разница минимальна, но с ростом размера файлов накладные расходы становятся существенными.

В целом FUSE — это удобный инструмент для разработки специализированных файловых систем, когда гибкость и простота разработки важнее максимальной производительности.
