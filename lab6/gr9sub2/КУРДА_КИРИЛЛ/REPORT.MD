# Лабораторная работа 6: FUSE файловая система

## 1. Цель работы
Изучение архитектуры виртуальной файловой системы (VFS) и FUSE, реализация собственного FUSE-плагина с различными режимами работы: passthrough, ROT13 и uppercase.

---

## 2. Теоретическая часть

### Архитектура VFS и роль FUSE
VFS (Virtual File System) — это абстракция файловой системы в ядре Linux, которая позволяет работать с разными файловыми системами одинаковым образом.  

FUSE (Filesystem in Userspace) позволяет реализовать файловую систему в пространстве пользователя. Ядро Linux через VFS перенаправляет системные вызовы на FUSE kernel module, которая общается с userspace процессом (нашей программой).

**Схема взаимодействия:**

```

Приложение (open, read, write)
│
▼
VFS
│
▼
FUSE kernel module
│
▼
Пользовательский FUSE процесс

````

### Реализованные file operations
- `getattr` — получение метаданных файла/директории
- `readdir` — чтение содержимого директории
- `open` — открытие файла
- `read` — чтение файла с опциональной трансформацией (ROT13, uppercase)
- `write` — запись в файл с применением трансформаций
- `create` — создание файла
- `unlink` — удаление файла
- `mkdir` / `rmdir` — создание и удаление директорий

## 3. Ход выполнения

### Задание A: Passthrough FUSE

#### Реализация
Программа `myfuse` монтирует директорию источника (`/tmp/source`) в точку монтирования (`/mnt/fuse`). Все операции перенаправляются напрямую к реальной файловой системе. Для логирования каждой операции используется функция `logop`.

#### Команды для сборки и запуска
```bash
make
mkdir -p /tmp/source /mnt/fuse
./myfuse /tmp/source /mnt/fuse
````

#### Тестирование

```bash
$ echo "test" > /mnt/fuse/file.txt
[2025-01-15 10:30:42] CREATE: /file.txt (result: 0)
[2025-01-15 10:30:42] WRITE: /file.txt, 5 bytes (result: 5)

$ cat /mnt/fuse/file.txt
[2025-01-15 10:30:45] OPEN: /file.txt (result: 0)
[2025-01-15 10:30:45] READ: /file.txt, 5 bytes (result: 5)
test

$ mkdir /mnt/fuse/testdir
[2025-01-15 10:31:00] MKDIR: /testdir (result: 0)

$ rmdir /mnt/fuse/testdir
[2025-01-15 10:31:10] RMDIR: /testdir (result: 0)

$ rm /mnt/fuse/file.txt
[2025-01-15 10:31:20] UNLINK: /file.txt (result: 0)
```

### Задание B: ROT13 FUSE

Запуск с трансформацией ROT13:

```bash
./myfuse /tmp/source /mnt/fuse --mode=rot13
```

Пример:

```bash
$ echo "Hello World" > /mnt/fuse/secret.txt
[2025-11-23 14:14:08] CREATE: /secret.txt (result: 0)
[2025-11-23 14:14:08] WRITE: /secret.txt (result: 12)

$ cat /tmp/source/secret.txt
Uryyb Jbeyq

$ cat /mnt/fuse/secret.txt
Hello World
```

### Задание C: Uppercase FUSE

Запуск с трансформацией в верхний регистр:

```bash
./myfuse /tmp/source /mnt/fuse --mode=upper
```

Пример:

```bash
$ echo "hello world" > /tmp/source/test.txt
$ cat /mnt/fuse/test.txt
HELLO WORLD
```


* **IOPS:** создание множества маленьких файлов (1000 файлов по 1KB) и измерение времени.

**Ожидаемые выводы тестирования:**

* Overhead от FUSE: context switch между kernel и userspace добавляет 20–40% задержки.
* Bottleneck на мелких операциях: FUSE хуже на большом количестве мелких файлов.
* Для больших последовательных чтений overhead меньше.

## 5. Ответы на контрольные вопросы

```
1. 
Что такое VFS (Virtual File System) и зачем она нужна?
VFS — это абстракция файловой системы в ядре Linux, которая позволяет работать с разными файловыми системами единообразно через общий интерфейс системных вызовов.

2. 
Объясните разницу между inode, dentry и file descriptor.
inode — структура, содержащая метаданные файла (размер, права, указатели на данные); 
dentry — элемент кэша директорий, ускоряет поиск файлов по имени; 
file descriptor — индекс открытого файла для процесса, используется для чтения/записи.

3. 
Что хранится в структуре struct inode?
Метаданные файла: права доступа, UID/GID, размер, временные метки (atime, mtime, ctime), ссылки на блоки данных, тип файла.

4. 
Что такое superblock и какую информацию он содержит?
Superblock — структура, описывающая файловую систему целиком: размер FS, количество блоков и inode, информация о журнале, тип FS, состояние и параметры монтирования.

5. 
Как работает кеш dentry и зачем он нужен?
Dentry cache хранит соответствие имени файла → inode, ускоряя операции поиска и доступ к файлам без повторного обращения к диску.

6. 
Как FUSE взаимодействует с ядром Linux?
Ядро Linux через VFS перенаправляет системные вызовы в FUSE kernel module, которая пересылает запросы в userspace процесс (нашу FS), затем возвращает результат обратно в ядро.

7. 
Опишите путь системного вызова read() в FUSE FS.
Приложение вызывает read() → VFS → FUSE kernel module → userspace FUSE процесс → чтение из реального файла или трансформация → возвращение данных через kernel → приложению.

8. 
Почему FUSE работает медленнее нативных kernel FS?
Из-за context switch между kernel и userspace и дополнительного копирования данных между пространствами памяти.

9. 
Какие преимущества дает разработка FS в userspace?
- Безопасность: сбои FS не крашат ядро; 
- Удобство разработки и отладки; 
- Портируемость на разные ОС.

10. 
Приведите примеры популярных FUSE файловых систем (sshfs, GCS FUSE, etc.).
sshfs, gcsfuse, encfs, unionfs, rclone mount.

11. 
Что делает операция getattr() и когда она вызывается?
Возвращает метаданные файла/директории (размер, права, временные метки). Вызывается при stat(), ls, open() и других системных вызовах.

12. 
В чем разница между open() и create()?
open() открывает существующий файл, create() создаёт новый файл и возвращает дескриптор.

13. 
Почему read() принимает параметр offset?
Чтобы можно было читать из середины файла, не только с начала, и поддерживать произвольный доступ.

14. 
Как readdir() возвращает список файлов?
readdir() использует callback (filler) для добавления имен файлов в буфер, возвращаемый пользователю.

15. 
Что должна возвращать getattr() для директории?
Метаданные директории: права, размер (обычно 4096), временные метки, количество ссылок, тип (directory).

16. 
Что такое атрибуты файла? Приведите примеры.
Информация о файле: размер, права, владельцы, временные метки, тип файла.

17. 
Что означают биты прав доступа (rwxrwxrwx)?
Права для владельца, группы и остальных: r — чтение, w — запись, x — выполнение.

18. 
Объясните разницу между mtime, atime и ctime.
mtime — время последней модификации содержимого; 
atime — время последнего доступа; 
ctime — время изменения inode или метаданных.

19. 
Что такое hard link и как он отличается от symbolic link?
Hard link — альтернативное имя для inode, разделяет содержимое файла; 
Symbolic link — отдельный файл, содержащий путь к другому файлу, может ссылаться на другую FS.

20. 
Как FS определяет размер файла?
Размер хранится в inode и обновляется при записи/удалении данных.

21. 
Что такое блок в файловой системе?
Минимальная единица хранения данных на диске, обычно 4KB.

22. 
Объясните принцип непрерывного размещения файлов (contiguous allocation).
Файл хранится в последовательных блоках на диске, что ускоряет чтение, но сложно управлять фрагментацией.

23. 
Как работает организация через связанный список блоков (linked allocation)?
Каждый блок содержит указатель на следующий, позволяя хранить файлы в разрозненных блоках; медленнее случайный доступ, но легко расширять.

24. 
Что такое индексный узел (inode-based allocation)?
Inode содержит указатели на блоки файла; поддерживает прямые, косвенные и двойные косвенные указатели для хранения больших файлов.

25. 
Сравните ext4 и btrfs по структуре хранения данных.
ext4 — классическая inode-based FS с журналированием, блоки фиксированного размера; 
btrfs — copy-on-write FS, поддерживает снапшоты, динамическое управление блоками, B-tree для метаданных.

26. 
Почему большие файлы читаются быстрее, чем много мелких?
Из-за уменьшения количества операций открытия/закрытия и меньшего overhead на syscalls.

27. 
Что такое read-ahead и как он улучшает производительность?
Read-ahead предзагружает последовательные блоки файла в кэш, уменьшая количество ожиданий диска.

28. 
Как page cache ускоряет доступ к файлам?
Данные хранятся в оперативной памяти, последующие чтения происходят без обращения к диску.

29. 
Почему запись на SSD быстрее, чем на HDD?
SSD не имеет механического движения головок, доступ к блокам практически мгновенный, нет seek latency.

30. 
Какие параметры влияют на производительность FUSE FS?
- Размер буфера (read/write); 
- Количество контекстных переключений; 
- Используемый режим трансформации; 
- Размер файлов и количество мелких файлов; 
- Параметры ядра FUSE (max threads, direct_io, kernel cache).
```
