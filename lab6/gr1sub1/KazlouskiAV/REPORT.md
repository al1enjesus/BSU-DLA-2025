# Отчёт по лабораторной работе №6: Файловые системы FUSE

## 1. Цель работы

Целью лабораторной работы является изучение архитектуры виртуальной файловой системы (VFS) в Linux, освоение механизма FUSE (Filesystem in Userspace), реализация пользовательской файловой системы, а также оценка её производительности по сравнению с нативными файловыми системами.

## 2. Теоретическая часть

### Архитектура VFS и роль FUSE

**VFS (Virtual File System)** — это абстрактный слой в ядре Linux, обеспечивающий единый интерфейс для взаимодействия приложений с различными файловыми системами (ext4, btrfs, NFS, FUSE и др.). VFS оперирует такими сущностями, как *superblock*, *inode*, *dentry* и *file*, скрывая детали реализации конкретной ФС.

**FUSE** позволяет реализовывать файловые системы в пользовательском пространстве (userspace), без написания кода для ядра. Драйвер FUSE в ядре перехватывает системные вызовы от приложений и перенаправляет их через специальный файл `/dev/fuse` в userspace-процесс, где библиотека **libfuse** преобразует их в вызовы пользовательских функций.

### Реализованные file operations

В рамках лабораторной работы реализованы следующие операции:

- `getattr` — получение атрибутов файла (`stat`)
- `readdir` — перечисление содержимого директории
- `open` — открытие файла
- `read` / `write` — чтение и запись данных
- `create` — создание нового файла
- `unlink`, `mkdir`, `rmdir` — управление файлами и директориями

Для режима **tar** реализованы только `getattr`, `readdir`, `open`, `read` (read-only).

Для режима **мониторинга** добавлена генерация виртуального файла `.stats`.

# Задание B: Archive Filesystem (read-only)

## Реализация

Реализована read-only FUSE-файловая система для .tar-архивов. При запуске с флагом -t программа загружает архив в память (через mmap), 
парсит заголовки и строит виртуальную структуру файлов. Поддерживаются только текстовые операции чтения.

```bash
tar -cf test.tar file1.txt file2.txt
./myfuse -t test.tar /mnt/fuse
```

### Тестирование
```bash
$ ls /mnt/fuse/
file1.txt  file2.txt

$ cat /mnt/fuse/file1.txt
Hello from tar!

$ echo "fail" > /mnt/fuse/file1.txt
-bash: /mnt/fuse/file1.txt: Permission denied  # read-only
```

### Выводы

FUSE — мощный и гибкий механизм для создания файловых систем без вмешательства в ядро.
Реализация passthrough, tar-архива и мониторинга оказалась достаточно простой благодаря libfuse.
Производительность FUSE уступает нативным ФС, особенно при работе с множеством мелких файлов.
Однако для многих прикладных задач (облачные хранилища, шифрование, архивы) overhead оправдан удобством и безопасностью.
Наибольшие сложности возникли при корректной обработке путей, ошибок и потокобезопасности статистики.

## Ответы на контрольные вопросы

1. VFS — абстрактный слой ядра, унифицирующий доступ ко всем ФС через единый API.
2. inode — метаданные файла; dentry — кэш имя → inode; fd — дескриптор открытого файла в процессе.
3. В struct inode: права, размер, временные метки, ссылки на блоки данных.
4. superblock — метаданные ФС: тип, размер, свободное место, блоки.
5. dentry cache ускоряет преобразование пути в inode, избегая повторных обращений к диску.
6. Через /dev/fuse: ядро пишет запрос → userspace читает → обрабатывает → отправляет ответ.
7. read() → VFS → FUSE kernel → /dev/fuse → libfuse → ваша функция → ответ обратно.
8. Из-за переключений контекста, копирования данных и отсутствия оптимизаций ядра.
9. Безопасность (падение не роняет систему), простота отладки, использование обычных библиотек.
10. sshfs, rclone, gcsfuse, mergerfs, encfs.
11. getattr() возвращает атрибуты (stat); вызывается при ls -l, stat, открытии файла.
12. open() — для существующего файла; create() — создаёт новый при открытии.
13. Позволяет читать из любого смещения без lseek (поддержка random access).
14. Через callback filler(), который вызывается для каждого файла в директории.
15. Для директории st_mode должен содержать S_IFDIR, st_nlink ≥ 2.
16. Атрибуты: права, владелец, размер, временные метки, флаги.
17. rwxrwxrwx = владелец/группа/все: чтение/запись/исполнение.
18. mtime — время модификации содержимого; atime — последнего доступа; ctime — изменения метаданных.
19. Hard link — второе имя для того же inode; symlink — отдельный файл с путём.
20. Размер хранится в st_size поля struct stat.
21. Блок — минимальная единица выделения на диске (обычно 4 КБ).
22. Contiguous allocation — файл занимает последовательные блоки; быстро, но вызывает фрагментацию.
23. Linked allocation — каждый блок содержит указатель на следующий; медленный доступ.
24. Inode-based — inode содержит список или дерево блоков (как в ext4).
25. ext4 — традиционная inode-ФС; btrfs — копирование при записи, снапшоты, контроль целостности.
26. Меньше системных вызовов и накладных расходов на открытие/закрытие.
27. Read-ahead — ядро предзагружает следующие блоки, уменьшая задержки.
28. Page cache хранит данные в ОЗУ; повторный доступ — мгновенный.
29. У SSD нет механических частей; случайный доступ почти так же быстр, как последовательный.
30. Context switch, копирование данных, латентность userspace, отсутствие page cache в FUSE (в старых версиях).
