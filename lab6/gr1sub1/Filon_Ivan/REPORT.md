## Ответы на контрольные вопросы

### Архитектура файловых систем

**1. Что такое VFS (Virtual File System) и зачем она нужна?**

VFS — уровень абстракции в ядре Linux, который дает общий интерфейс для работы с разными типами файловых систем. VFS дает возможность использовать одинаковые системные вызовы (например, open) независимо от типа файловой системы.

**2. Объясните разницу между inode, dentry и file descriptor.**

- **inode** — структура данных, которая хранит метаданные файла. Уникальная пара: файл - inode.
- **dentry** (или directory entry) — кеш-запись, которая связывает имя файла и inode, что ускоряет разрешение путей (`/home/user/file.txt` → inode).
- **file descriptor** — целочисленный идентификатор открытого файла в процессе, который указывает на запись в таблице открытых файлов, которая ссылается на inode.

**3. Что хранится в структуре struct inode?**

- Тип файла (обычный файл, директория)
- Права доступа
- Владелец
- Размер файла
- Временные метки
- Количество hard links
- Указатели на блоки данных
- Операции файловой системы

**4. Что такое superblock и какую информацию он содержит?**

Superblock — метаданные файловой системы, которые хранятся в начале раздела. Среди них:
- Размер ФС
- Размер блока
- Количество свободных блоков и inode
- Magic number (идентификатор типа ФС)
- Флаги монтирования
- Указатель на корневой inode

**5. Как работает кеш dentry и зачем он нужен?**

Dentry cache (dcache) отвечает за хранение пары "путь → inode" в оперативной памяти, то есть при наличии записи в кэше значительно ускоряется разрешение пути

### FUSE

**6. Как FUSE взаимодействует с ядром Linux?**

FUSE использует модуль ядра `fuse.ko` и устройство `/dev/fuse`. Как устроено взаимодействие:
1. Системный вызов со стороын приложения
2. VFS перенаправляет в FUSE kernel module
3. FUSE kernel записывает этот запрос в очередь `/dev/fuse`
4. FUSE daemon читает этот запрос из `/dev/fuse`
5. FUSE daemon обрабатывает этот запрос и пишет ответ в `/dev/fuse`
6. FUSE kernel дает ответ через VFS приложению

**7. Опишите путь системного вызова read() в FUSE FS.**

```
1. Вызов в приложении read(fd, buf, 4096)
2. glibc: системный вызов sys_read()
3. VFS: vfs_read() → находит file_operations
4. FUSE kernel: fuse_file_read() → формируется запрос FUSE_READ
5. /dev/fuse: передает запрос в userspace через device
6. libfuse: fuse_session_receive_buf() читает этот запрос
7. FUSE daemon: вызывается функция чтения в приложении
8. FUSE daemon: возвращает данные через fuse_reply_buf()
9. /dev/fuse: ответ идет обратно в kernel
10. FUSE kernel: копирует данные в пользовательский буфер
11. VFS: возвращает количество прочитанных байт
12. Получение результата в приложении
```

**9. Какие преимущества дает разработка FS в userspace?**

- **Безопасность**: нет угрозы для ядра
- **Отладка**: доступны разные варианты, например, можно использовать gdb, valgrind, strace
- **Библиотеки**: доступ к userspace библиотекам (libcurl, libssl)
- **Языки программирования**: выбор не гораничивается только С
- **Быстрая разработка**: не надо пересобирать ядро
- **Переносимость**: универсальность кода относительно ОС, на которой он заупскается

### File operations

**11. Что делает операция getattr() и когда она вызывается?**

`getattr()` дает атрибуты файла, она вызывается при использовании:
- `ls -l` — для получения размера, прав, времени модификации
- `stat` — прямой запрос атрибутов
- Открытии файла — проверка существования и прав
- Перехода по директориям — проверка типа (файл/директория)

Возвращает структуру `struct stat` с такими полями, как: `st_mode`, `st_size`, `st_mtime`, `st_uid`, `st_gid`.

**12. В чем разница между open() и create()?**

- **open()** — открывает существующий файл или создает с флагом `O_CREAT`
- **create()** — всегда создает новый файл с указанными правами

**13. Почему read() принимает параметр offset?**

Offset необходимо для отслеживания позиции в файле для чтения, что позволяет читать любую часть файла без sequential чтения, а также удобно при многопотчоности, так как потоки могут читать разные части.

**14. Как readdir() возвращает список файлов?**

Использует callback-функцию `filler` для добавления каждой записи, то какждый вызов добавляет одну запись

**15. Что должна возвращать getattr() для директории?**

Для директории `getattr()` должна установить:
- **st_mode**: `S_IFDIR | permissions`
- **st_nlink**: количество поддиректорий
- **st_size**: 0 или размер директории (зависит от файловой системы)
- **st_uid/st_gid**: владелец
### Метаданные и атрибуты

**16.  Что такое атрибуты файла?  Приведите примеры.**

Атрибуты файла — метаданные, описывающие свойства файла:

**Стандартные атрибуты:**
- **Размер**: количество байт
- **Права доступа**: owner/group/others
- **Владелец**: UID, GID
- **Временные метки**: atime, mtime, ctime
- **Тип**

**Расширенные атрибуты:**
- **SELinux labels**: `security.selinux`
- **ACL**: `system.posix_acl_access`
- **Пользовательские**: `user.author`, `user.checksum`

**17. Что означают биты прав доступа (rwxrwxrwx)?**

9-битная маска прав доступа делится на 3 группы:
rwx (владелец) rwx (группа) rwx (остальные пользователи)

**Значение битов:**
- **r (4)**: read — чтение
- **w (2)**: write — запись/создание
- **x (1)**: execute — выполнение/вход

**18. Объясните разницу между mtime, atime и ctime.**

- **mtime** (modification time): фиксирует время последней модификации файла
    - Обновляется при `write()`, `truncate()`
    - Используется `make` для проверки актуальности

- **atime** (access time): фиксирует время последнего чтения
    - Обновляется при `read()`, `open()`
    - Часто отключается (`noatime`) для производительности

- **ctime** (change time): фиксирует время последней модификации метаданных
    - Обновляется при `chmod()`, `chown()`, `rename()`
    - Не может быть изменена пользователем

**19.  Что такое hard link и как он отличается от symbolic link?**

**Hard link:**
- Дополнительное имя для inode
- Все hard links равноправны
- Инкрементирует счетчик ссылок (`st_nlink`)
- Не может ссылаться на директории или файлы на других файловых системах
- Файл удаляется только при `st_nlink` = 0

**Symbolic link:**
- Отдельный файл, который содержит путь к целевому файлу
- Может ссылаться на несуществующие файлы (broken link)
- Может ссылаться на директории и файлы на других файловых систем
- У нее свой собственный inode

**20. Как FS определяет размер файла?**

По полю `st_size` структуры inode, там лежит размер файла.

### Физическая организация

**21. Что такое блок в файловой системе?**

Блок — минимальная единица дискового пространства, которой оперирует файловая система. Чаще всего кратен размеру сектора диска (512 байт).

**22. Объясните принцип непрерывного размещения файлов (contiguous allocation).**

Он подразумеваеь, что файл размещается в последовательных блоках диска.

**23. Как работает организация через связанный список блоков (linked allocation)?**

При такой организации каждый блок файла содержит указатель на следующий блок.

**24. Что такое индексный узел (inode-based allocation)?**

Это как раз inode, он содержит прямые и косвенные указатели на блоки данных файла.

### Производительность и оптимизация

**26. Почему большие файлы читаются быстрее, чем много мелких?**

Большие файлы читаются быстрее, потому что диск читает большие блоки быстрее, меньше системных вызово(за раз читаем больше), ОС умеет предсказывать следующие блоки.
А мелкие файлы требуют позиционирования головки для каждого, больше дополнительных операци и системных вызовов

**27. Что такое read-ahead и как он улучшает производительность?**

Read-ahead — предварительное чтение данных, которые могут понадобиться.

**Механизм работы:**
1. Детекция sequential access pattern
2. Увеличение размера read-ahead window
3. Асинхронное чтение в page cache
4. Приложение видит данные уже в памяти

**28.  Как page cache ускоряет доступ к файлам?**

Page cache — кеш файловых данных в оперативной памяти. При повтороных обращаениях читает сразу из памяти, а также поддерживает асинхронную запись, что тоже ускоряет

**29. Почему запись на SSD быстрее, чем на HDD?**

Потому что нет затрат времени на позиционирование головки, поддерживается random access и параллелизм

**30. Какие параметры влияют на производительность FUSE FS?**

**Системные параметры:**
- **big_writes**: увеличивает размер write запросов до 128KB
- **max_read**: максимальный размер read запроса
- **max_write**: максимальный размер write запроса
- **direct_io**: обходит page cache (для некеширующихся ФС)

**Архитектурные решения:**
- **Многопоточность**: обработка параллельных запросов
- **Batching**: объединение мелких операций
- **Кеширование**: уменьшение обращений к backend
- **Asynchronous I/O**: неблокирующие операции
