## 2. Теоретические основы

### 2.1. Virtual File System (VFS)

**VFS** — абстрактный слой в ядре Linux, предоставляющий единый интерфейс (системные вызовы `open()`, `read()`, `write()`) для работы с разнородными файловыми системами (ext4, NFS, FUSE и др.). Это позволяет приложениям взаимодействовать с ФС, не зная их внутреннего устройства.

### 2.2. Архитектура FUSE

**FUSE** — механизм для создания файловых систем в пользовательском пространстве. Драйвер FUSE в ядре перехватывает запросы от VFS и направляет их через специальный канал (`/dev/fuse`) в программу пользователя, где они обрабатываются библиотекой `libfuse`.

**Трассировка запроса `read()`:**  
Приложение → Системный вызов → VFS → Драйвер FUSE → `/dev/fuse` → `libfuse` → Пользовательская функция → Обратный путь с данными.

5. Ответы на контрольные вопросы
Архитектура файловых систем
VFS (Virtual File System): Абстрактный слой в ядре Linux, предоставляющий единый API для работы с различными ФС, обеспечивая их совместимость.

Разница между inode, dentry и file descriptor:

inode — метаданные файла на диске.

dentry — структура VFS, связывающая имя файла с его inode.

file descriptor — целочисленный идентификатор открытого файла в процессе.

Структура struct inode содержит: размер файла, права доступа, владельца, временные метки, указатели на блоки данных.

Superblock описывает ФС в целом: размер, тип, размер блока, количество inode.

Кеш dentry хранит в памяти связи "путь → inode", чтобы избежать повторного поиска на диске.

FUSE
Взаимодействие FUSE с ядром: Через драйвер FUSE, который перехватывает запросы VFS и перенаправляет их в userspace через /dev/fuse.

Путь системного вызова read() в FUSE: Приложение → VFS → Драйвер FUSE → /dev/fuse → libfuse → Пользовательский обработчик.

Причины меньшей производительности FUSE: Контекстные переключения и накладные расходы на копирование данных через границу ядро/userspace.

Преимущества разработки в userspace: Простота, безопасность (ошибка не приводит к панике ядра), возможность использования любых библиотек.

Примеры популярных ФС на FUSE: sshfs, s3fs, ext2fuse.

Операции с файлами
Операция getattr() получает атрибуты файла. Вызывается командами ls, stat и перед многими другими операциями.

Разница между open() и create(): open() открывает существующий файл, create() — создает новый.

Параметр offset в read() указывает позицию для чтения, что важно для многопоточного доступа.

readdir() возвращает список файлов через функцию-заполнитель filler().

getattr() для директории должна устанавливать флаг S_IFDIR в st_mode.

Метаданные и производительность
Атрибуты файла — его метаданные: права доступа, размер, владелец, временные метки.

Права доступа rwxrwxrwx: Три группы (владелец, группа, остальные) с правами на чтение (r), запись (w), выполнение (x).

Разница между mtime, atime, ctime:

mtime — время изменения содержимого.

atime — время последнего доступа.

ctime — время изменения метаданных.

Hard link vs Symbolic link: Hard link — дополнительное имя для того же inode. Symbolic link — отдельный файл, содержащий путь к цели.

Определение размера файла: Поле st_size в структуре inode.

Отсутствие реализации unlink() приведет к ошибке -ENOSYS, и файлы нельзя будет удалить.

Роль struct fuse_file_info (fi): Содержит флаги открытия файла и позволяет хранить пользовательские данные (например, дескриптор) для оптимизации.

Page cache и FUSE: Ядро кеширует данные файлов в ОЗУ. FUSE-ФС может потребовать инвалидации этого кеша (FUSE_INVAL_PAGE) для согласованности данных.

Write-back vs Write-through кэширование:

Write-through: Данные пишутся одновременно в кеш и на диск (надежно, медленно).

Write-back: Данные сначала пишутся в кеш, отложенная запись на диск (быстро, менее надежно).

Высокая задержка в FUSE обусловлена необходимостью контекстного переключения для каждой мелкой операции.

Большие файлы читаются быстрее из-за минимизации операций с метаданными и эффективного последовательного доступа.

FUSE оправдан, когда важна функциональность, а не скорость: удаленные ФС (sshfs), доступ к архивам/облакам, трансформация данных.

Защита от Path Traversal: Использование функции realpath() для получения абсолютного пути и строгий контроль конкатенации с базовой директорией.

statfs() возвращает статистику по всей ФС (общее/свободное место), используется командой df.

Факторы производительности FUSE: Частота контекстных переключений (главный фактор), размер блока I/O, эффективность кэширования в ядре.
