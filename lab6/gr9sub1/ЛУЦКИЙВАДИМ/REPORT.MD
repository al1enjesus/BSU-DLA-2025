## Теоретическая часть
### Архитектура VFS и FUSE
Virtual File System (VFS) представляет собой абстрактный уровень в ядре Linux, обеспечивающий унифицированный интерфейс для взаимодействия с разнородными файловыми системами. VFS позволяет приложениям использовать стандартные системные вызовы независимо от конкретного типа ФС.

FUSE (Filesystem in Userspace) - технология, позволяющая разрабатывать файловые системы в пользовательском пространстве без необходимости написания кода ядра. Драйвер FUSE в ядре перенаправляет операции VFS в userspace-процесс через специализированный протокол.

### Схема взаимодействия
Приложение (ls, cat, echo)
↓
VFS (ядро Linux)
↓
FUSE kernel module
↓ (протокол FUSE)
/dev/fuse
↓
libfuse (userspace)
↓
FUSE программа
↓
Реальная файловая система

## Ответы на контрольные вопросы
### Архитектура файловых систем
1. **Что такое VFS (Virtual File System) и зачем она нужна?**  
VFS - это абстрактный слой в ядре Linux, предоставляющий единый интерфейс для работы с различными файловыми системами. Необходима для обеспечения совместимости между разными ФС и упрощения разработки.

2. **Объясните разницу между inode, dentry и file descriptor.**  
- inode - структура метаданных файла (размер, права, блоки данных)
- dentry - кеш связей имен файлов с inode
- file descriptor - ссылка на открытый файл в процессе

3. **Что хранится в структуре struct inode?**  
Размер файла, права доступа, временные метки, владелец, указатели на блоки данных, счетчик ссылок.

4. **Что такое superblock и какую информацию он содержит?**  
Superblock описывает файловую систему в целом: размер, тип, количество свободных блоков, корневой inode.

5. **Как работает кеш dentry и зачем он нужен?**  
Dentry кеширует преобразование путей в inode для ускорения доступа к часто используемым файлам.

### FUSE
6. **Как FUSE взаимодействует с ядром Linux?**  
Через драйвер FUSE, который перехватывает VFS операции и перенаправляет их через /dev/fuse в userspace.

7. **Опишите путь системного вызова read() в FUSE FS.**  
Приложение → syscall → VFS → FUSE драйвер → /dev/fuse → libfuse → пользовательская функция read.

8. **Почему FUSE работает медленнее нативных kernel FS?**  
Из-за дополнительных context switch между kernel и userspace и копирования данных через границу.

9. **Какие преимущества дает разработка FS в userspace?**  
Безопасность, простота отладки, использование стандартных библиотек, отсутствие риска kernel panic.

10. **Приведите примеры популярных FUSE файловых систем.**  
sshfs, GVFS, NTFS-3G, EncFS, GCSFuse.

### File operations
11. **Что делает операция getattr() и когда она вызывается?**  
Возвращает метаданные файла. Вызывается при stat(), ls, открытии файла.

12. **В чем разница между open() и create()?**  
open() открывает существующий файл, create() создает новый.

13. **Почему read() принимает параметр offset?**  
Для поддержки не последовательного чтения и работы с несколькими потоками.

14. **Как readdir() возвращает список файлов?**  
Через функцию filler, которая добавляет имена файлов в буфер.

15. **Что должна возвращать getattr() для директории?**  
Тип S_IFDIR, размер обычно 4096, права доступа.

### Метаданные и атрибуты
16. **Что такое атрибуты файла? Приведите примеры.**  
Размер, права доступа, временные метки, владелец, тип файла.

17. **Что означают биты прав доступа (rwxrwxrwx)?**  
rwx для владельца, группы и остальных: read, write, execute.

18. **Объясните разницу между mtime, atime и ctime.**  
mtime - время модификации, atime - время доступа, ctime - время изменения метаданных.

19. **Что такое hard link и как он отличается от symbolic link?**  
Hard link - прямая ссылка на inode, symbolic link - файл с путем к целевому файлу.

20. **Как FS определяет размер файла?**  
Из поля st_size в inode, которое обновляется при записи.

### Физическая организация
21. **Что такое блок в файловой системе?**  
Минимальная единица выделения места на диске, обычно 4KB.

22. **Объясните принцип непрерывного размещения файлов.**  
Файл занимает последовательные блоки на диске. Быстрый доступ, но фрагментация.

23. **Как работает организация через связанный список блоков?**  
Каждый блок содержит указатель на следующий. Устраняет фрагментацию, но медленный доступ.

24. **Что такое индексный узел (inode-based allocation)?**  
Inode содержит прямые и косвенные указатели на блоки данных. Используется в ext*, UFS.

25. **Сравните ext4 и btrfs по структуре хранения данных.**  
ext4 - inode с прямыми/косвенными указателями, btrfs - B-дерево, copy-on-write.

### Производительность и оптимизация
26. **Почему большие файлы читаются быстрее, чем много мелких?**  
Меньше overhead на метаданные, лучше использование кеша, последовательный доступ.

27. **Что такое read-ahead и как он улучшает производительность?**  
Предварительное чтение следующих блоков в кеш до запроса приложения.

28. **Как page cache ускоряет доступ к файлам?**  
Кеширует часто используемые блоки в памяти, избегая обращений к диску.

29. **Почему запись на SSD быстрее, чем на HDD?**  
Отсутствие механических частей, параллельный доступ к ячейкам, низкая задержка.

30. **Какие параметры влияют на производительность FUSE FS?**  
Размер буферов, политики кеширования, количество потоков, размер блока.
