# Отчет по лабораторной работе 6 — Файловые системы FUSE

Черноокийй Д.И.

## 1. Цель работы
Изучить архитектуру виртуальной файловой системы (VFS) Linux и научиться создавать пользовательские файловые системы с использованием FUSE (Filesystem in Userspace). Понять принципы работы файловых операций, взаимодействие между ядром и userspace, а также оценить производительность userspace файловых систем.

## 2. Теоретическая часть
VFS — абстрактный слой в ядре, предоставляющий единый интерфейс для файловых систем. Он оперирует структурами: `superblock`, `inode`, `dentry` и `file`.

Схема взаимодействия:

Приложение → VFS (ядро) → FUSE kernel module → /dev/fuse → libfuse (userspace) →  программа

Реализованные file operations:
- `getattr` — чтение атрибутов (stat)
- `readdir` — чтение содержимого директории
- `open` — открыть файл
- `read` — чтение из файла (с поддержкой offset)
- `write` — запись в файл
- `create` — создание файла
- `unlink` — удаление
- `mkdir`, `rmdir` — создание/удаление директорий
- `release` — закрытие файла

## 3. Ход выполнения
### Задание A: Passthrough FUSE
Реализована файловая система, зеркалирующая указанную директорию `source` в точку монтирования. Все операции проксируются в реальную FS. Каждая операция логируется в `stderr`.

Ключевые функции: реализованы в `src/operations.c` (`fs_getattr`, `fs_readdir`, `fs_open`, `fs_read`, `fs_write`, `fs_create`, `fs_unlink`, `fs_mkdir`, `fs_rmdir`, `fs_release`).

Команды для запуска:
```bash
make
mkdir -p /tmp/source /mnt/fuse
./myfuse /tmp/source /mnt/fuse -f
```

Примеры логов при тестировании:
```
[2025-01-15 10:30:42] CREATE: /file.txt (result: 0)
[2025-01-15 10:30:42] WRITE: /file.txt (result: 11)
[2025-01-15 10:30:45] OPEN: /file.txt (result: 0)
[2025-01-15 10:30:45] READ: /file.txt (result: 11)
```

### Задание B: ROT13 Filesystem (вариант 2)
Реализовано ROT13-преобразование: при записи в FS данные шифруются ROT13 и сохраняются в `source`; при чтении через FUSE данные расшифровываются.

Пример:
```bash
./myfuse /tmp/source /mnt/fuse -m rot13 -f
echo "Hello World" > /mnt/fuse/secret.txt
# на диске: Uryyb Jbeyq
cat /mnt/fuse/secret.txt # показывает Hello World
```

### Задание C: Uppercase Filesystem (вариант 2)
Реализован режим `uppercase`: при чтении через FUSE всё содержимое конвертируется в верхний регистр. Запись работает как обычно.

Пример:
```bash
./myfuse /tmp/source /mnt/fuse -m uppercase -f
cat /mnt/fuse/test.txt # выводит содержимое в UPPERCASE
```

Короткие выводы по реальным данным:

- `open()` в FUSE показал заметный overhead: на нашей машине `native` средний open ≈ 0.005 ms, в FUSE режимах — ~0.32–0.36 ms (увеличение ~60–70× для этих тестов), что подчёркивает накладные расходы на переключения контекста и обработку в userspace (на небольших операциях FUSE даёт заметное замедление).
- `read()` 4KB: `native` ≈ 0.0035 ms, FUSE ≈ 0.12–0.14 ms — FUSE добавляет накладные расходы, но они становятся менее критичными для больших последовательных операций.
- `write()` показывает более высокий разброс; режим `rot13` немного дешевле чем `passthrough` в этих измерениях (возможно артефакт, зависит от кэшей и IO-синхронизации).

## 5. Ответы на контрольные вопросы
(здесь приведены ответы на все вопросы, требуемые в задании)

1. Что такое VFS и зачем она нужна?
- VFS (Virtual File System) — абстрактный слой в ядре Linux, который предоставляет единый интерфейс для работы с файловыми системами разного типа. Это позволяет приложениям использовать одни и те же системные вызовы независимо от конкретной реализации ФС.

2. Объясните разницу между inode, dentry и file descriptor.
- inode хранит метаданные файла (размер, права, временные метки, указатели на блоки).
- dentry — кеш имен директорий, связывает имя файла и inode.
- file descriptor — дескриптор, который пользовательская программа использует для доступа к открытому файлу; он ссылается на структуру `file` в ядре, содержащую позицию чтения и т.д.

3. Что хранится в struct inode?
- Метаданные файла: права доступа, UID/GID, размеры, временные метки, указатели на блоки/индексы и т.д.

4. Что такое superblock и какую информацию он содержит?
- superblock описывает файловую систему в целом (общее число блоков, размер блоков, список свободных блоков, метаданные о файловой системе).

5. Как работает кеш dentry и зачем он нужен?
- dentry cache ускоряет поиск по путям, кэшируя соответствие между именами и inode, снижая количество обращений к диску и повышая производительность.

6. Как FUSE взаимодействует с ядром Linux?
- Ядро перенаправляет VFS операции в FUSE kernel module. Модуль общается с userspace через /dev/fuse; libfuse в userspace принимает запросы и вызывает callback-функции вашего процесса.

7. Опишите путь системного вызова read() в FUSE FS.
- Приложение вызывает read(fd,...)
- Системный вызов в ядре → VFS → FUSE kernel module → сообщение в /dev/fuse → libfuse → ваш userspace процесс → ваша `read` функция читает/генерирует данные → возвращает их обратно через протокол → ядро → приложение.

8. Почему FUSE работает медленнее нативных kernel FS?
- Дополнительные context-switch'и между ядром и userspace, дополнительное копирование данных, задержки IPC.

9. Какие преимущества дает разработка FS в userspace?
- Проще отладка, отсутствие риска kernel panic, можно использовать любые библиотеки userspace.

10. Приведите примеры популярных FUSE файловых систем.
- sshfs, gcsfuse, rclone mount, encfs, ntfs-3g.

11. Что делает операция getattr() и когда она вызывается?
- Возвращает атрибуты файла (stat). Вызывается при обращениях, требующих метаданных (ls -l, open и т.д.).

12. В чем разница между open() и create()?
- open открывает существующий файл; create создает новый (эквивалент open с O_CREAT).

13. Почему read() принимает параметр offset?
- Для поддержки чтения в произвольной позиции (positional reads) и повторяемости операций без изменения позиции file descriptor.

14. Как readdir() возвращает список файлов?
- Через callback `filler(buf, name, stat, offset, flags)`; FUSE собирает эти имена и возвращает их в VFS.

15. Что должна возвращать getattr() для директории?
- Тип S_IFDIR, права на директорию, количество ссылок, размер (обычно 4096) и временные метки.

16. Что такое атрибуты файла? Примеры.
- Права доступа, владелец, группа, размер, временные метки (atime, mtime, ctime), тип файла.

17. Что означают биты прав доступа (rwxrwxrwx)?
- Права чтения/записи/выполнения для owner, group, others.

18. Объясните разницу между mtime, atime и ctime.
- mtime — время последней модификации содержимого; atime — последнее время доступа; ctime — время последнего изменения метаданных (или inode).

19. Что такое hard link и как он отличается от symbolic link?
- Hard link — ещё одно имя для того же inode. Символьная ссылка — специальный файл, указывающий путь к другому файлу.

20. Как FS определяет размер файла?
- В inode хранится размер в байтах.

21. Что такое блок в файловой системе?
- Минимальная единица хранения данных (например, 4KB).

22. Объясните принцип непрерывного размещения файлов (contiguous allocation).
- Файл хранится в последовательных блоках на диске; просто и быстро для последовательного доступа, но фрагментация может быть проблемой.

23. Как работает организация через связанный список блоков (linked allocation)?
- Каждый блок содержит указатель на следующий блок; легко расширять, но неэффективно для случайного доступа.

24. Что такое индексный узел (inode-based allocation)?
- inode содержит указатели на блоки или индексы, включая прямые/непервые/двойные индексы для организации блоков.

25. Сравните ext4 и btrfs по структуре хранения данных.
- ext4 использует inode + extent, ориентирован на стабильность и производительность; btrfs ориентирован на снапшоты, копирование при записи (COW), встроенную целостность и более сложную метадата-структуру.

26. Почему большие файлы читаются быстрее, чем много мелких?
- Меньше накладных расходов на syscalls и seek'и; лучше эффективность read-ahead и последовательных IO.

27. Что такое read-ahead и как он улучшает производительность?
- Предзагрузка данных в кеш заранее, чтобы сократить ожидание при последовательном чтении.

28. Как page cache ускоряет доступ к файлам?
- Хранит недавно используемые страницы в памяти, уменьшая обращения к диску.

29. Почему запись на SSD быстрее, чем на HDD?
- SSD не имеет механических задержек, обеспечивает низкое время доступа и высокую пропускную способность случайных операций.

30. Какие параметры влияют на производительность FUSE FS?
- Режим работы (sync/async), размер буферов, overhead IPC, реализация callbacks, количество syscalls.
