## 2. Теоретическая часть

### Архитектура VFS и FUSE

**Virtual File System (VFS)** - это абстрактный слой в ядре Linux, который предоставляет единый интерфейс для работы с различными файловыми системами. VFS позволяет приложениям использовать стандартные системные вызовы независимо от типа файловой системы.

**FUSE (Filesystem in Userspace)** - технология, позволяющая создавать файловые системы в пользовательском пространстве без необходимости написания кода для ядра.

### Схема взаимодействия:

```
Приложение (ls, cat, echo)
       ↓
   Системные вызовы (open, read, write)
       ↓
   VFS (ядро Linux)
       ↓
  FUSE kernel module
       ↓ (через /dev/fuse)
  libfuse (userspace)
       ↓
  Ваша FUSE программа
       ↓
  Реальная файловая система
```

**Ключевые структуры данных:**
- `struct fuse_operations` - содержит указатели на функции файловых операций
- `struct stat` - информация о файле (метаданные)
- `struct fuse_file_info` - информация об открытом файле
- `struct fuse_context` - контекст выполнения операции (содержит информацию о пользователе)

```c
static int check_access_permissions_impl(const char *path, int mode) {
    struct fuse_context *context = fuse_get_context();
    struct stat st;
    
    if (lstat(path, &st) == -1) {
        return -errno;
    }
    
    // Проверка прав для владельца, группы и других пользователей
    if (uid == st.st_uid) {
        if (!(st.st_mode & (mode << 6))) return -EACCES;
    } else if (gid == st.st_gid) {
        if (!(st.st_mode & (mode << 3))) return -EACCES;
    } else {
        if (!(st.st_mode & mode)) return -EACCES;
    }
    return 0;
}
```

```c
char* build_fullpath_safe(const char *base, const char *path, int *error_code) {
    // Канонизация базового пути
    char *canonical_base = canonicalize_path(base);
    
    // Проверка безопасности
    if (strstr(path, "..") != NULL) {
        *error_code = -EACCES;
        return NULL;
    }
    
    // Безопасное объединение путей
    char full_path[PATH_MAX];
    int written = snprintf(full_path, sizeof(full_path), "%s%s", 
                          canonical_base, path);
    
    // Проверка границ буфера
    if (written >= (int)sizeof(full_path)) {
        *error_code = -ENAMETOOLONG;
        return NULL;
    }
    
    return canonicalize_path(full_path);
}
```

**Универсальная обработка операций:**
```c
static int handle_file_operation(const char *operation, const char *path,
                                int (*file_op)(const char*, int*), 
                                const char *success_log) {
    int error_code = 0;
    char *full_path = get_full_path_or_error(path, &error_code);
    if (!full_path) {
        fprintf(stderr, "[%s] %s: %s (error: %s)\n",
                get_timestamp(), operation, path, strerror(-error_code));
        return error_code;
    }
    
    // Выполнение операции и логирование
    int result = file_op(full_path, &error_code);
    free(full_path);
    return error_code;
}
```

## 5. Ответы на контрольные вопросы

### Архитектура файловых систем

**1. Что такое VFS (Virtual File System) и зачем она нужна?**

VFS - это абстрактный слой в ядре Linux, который предоставляет единый интерфейс для работы с различными файловыми системами. Она нужна для:

- **Унификации доступа** - приложения используют одни и те же системные вызовы независимо от ФС
- **Расширяемости** - возможность добавления новых типов файловых систем
- **Совместимости** - поддержка различных форматов ФС (ext4, NTFS, FAT и др.)
- **Кеширования** - общий кеш dentry и inode для всех ФС

**2. Как FUSE обеспечивает безопасность при работе с файловыми операциями?**

FUSE предоставляет несколько механизмов безопасности:
- **Изоляция** - файловая система работает в userspace, ошибки не приводят к падению ядра
- **Контекст пользователя** - каждая операция выполняется с правами пользователя, вызвавшего её
- **Проверка путей** - FUSE проверяет корректность путей перед передачей в userspace
- **Ограничения** - возможность установки лимитов на операции

**3. Какие меры безопасности были реализованы в вашей FUSE файловой системе?**

В реализации были добавлены:
- **Проверка path traversal** - блокировка путей с ".."
- **Канонизация путей** - использование realpath() для нормализации
- **Проверка прав доступа** - детальная проверка прав пользователя
- **Валидация параметров** - проверка размеров и смещений операций
- **Граничные проверки** - обработка длинных путей и специальных символов

### FUSE и безопасность

**6. Как обрабатываются симлинки в FUSE файловой системе?**

В реализации используется `lstat()` вместо `stat()` в операции `getattr()`, что позволяет:
- Корректно обрабатывать метаданные симлинков
- Избежать нежелательного разыменования
- Сохранять информацию о типе файла (симлинк)

**7. Какие риски безопасности существуют при разработке FUSE FS и как их mitigiate?**

Основные риски и методы их устранения:
- **Path traversal** → Проверка наличия ".." в путях, канонизация
- **Race conditions** → Atomic операции, минимальное время между check и use
- **Memory leaks** → Единообразное освобождение ресурсов, использование Valgrind
- **Buffer overflows** → Использование безопасных функций (snprintf, strncpy)

### File operations и надежность

**11. Как обрабатываются ошибки в операциях файловой системы?**

Используется единообразная система обработки ошибок:
- Все ошибки возвращаются как отрицательные коды errno
- Каждая ошибка логируется с детальной информацией
- Ресурсы освобождаются даже при ошибках
- Система продолжает работу после ошибок

**12. Какие меры приняты для предотвращения утечек памяти?**

- Единообразное освобождение путей через `free()`
- Использование `realpath()` с последующим `free()`
- Проверка всех путей возврата в функциях
- Освобождение ресурсов в блоке `finally` (через goto)

**15. Как система ведет себя при достижении лимитов (например, максимального количества открытых файлов)?**

Система корректно обрабатывает лимиты:
- Возвращает `-EMFILE` при превышении лимита файловых дескрипторов
- Логирует ошибку для диагностики
- Продолжает работу с другими операциями
