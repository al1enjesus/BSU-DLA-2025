## 2. Теоретическая часть

### 2.1 Virtual File System (VFS)

VFS — это абстрактный слой в ядре Linux, который предоставляет единый интерфейс для работы с различными файловыми системами. VFS позволяет приложениям использовать одни и те же системные вызовы независимо от типа файловой системы.

**Ключевые структуры VFS:**
- **superblock** — описывает файловую систему в целом
- **inode** — метаданные файла (размер, права, временные метки)
- **dentry** — кеш имен директорий (связывает имя файла с inode)
- **file** — открытый файл (file descriptor, позиция чтения)

### 2.2 FUSE (Filesystem in Userspace)

FUSE позволяет создавать файловые системы в userspace без написания кода для ядра. Драйвер FUSE в ядре перенаправляет VFS операции в userspace процесс через специальный протокол.

**Архитектура взаимодействия:**

```
Приложение (cat, ls, cp)
       ↓ (системные вызовы)
   VFS (ядро Linux)
       ↓ (проверка типа ФС)
  FUSE kernel module
       ↓ (протокол FUSE через /dev/fuse)
  libfuse (userspace)
       ↓ (вызов функций)
  Наша FUSE программа
       ↓ (обращение к реальной ФС)
  Реальная файловая система
```

**Преимущества FUSE:**
- Разработка в userspace (проще отладка, нет риска kernel panic)
- Возможность использовать обычные библиотеки
- Безопасность (ошибка не роняет систему)

**Недостатки FUSE:**
- Overhead на context switch между kernel и userspace (медленнее на 20-40%)
- Дополнительное копирование данных через kernel/userspace boundary

### 2.3 Реализованные file operations

В работе были реализованы следующие операции:
- `getattr()` — получение метаданных файла (аналог stat)
- `readdir()` — чтение содержимого директории
- `open()` — открытие файла
- `read()` — чтение данных из файла
- `write()` — запись данных в файл
- `create()` — создание нового файла
- `unlink()` — удаление файла
- `mkdir()` — создание директории
- `rmdir()` — удаление директории

## 3. Ход выполнения

### 3.1 Задание A: Passthrough FUSE filesystem

#### Описание
Реализована простая FUSE файловая система, которая "зеркалирует" существующую директорию с логированием всех операций.

#### Реализация
Основные функции:
- Все операции проксируются в настоящую файловую систему
- Каждая операция логируется в stderr с форматом: `[TIMESTAMP] OPERATION: path (result)`
- Использует базовую директорию из аргумента командной строки

#### Команды для запуска
```bash
# Сборка
make passthrough_fs

# Создание директорий
mkdir -p /tmp/lab6_source /tmp/lab6_mount

# Запуск
./bin/passthrough_fs /tmp/lab6_source /tmp/lab6_mount

# Для foreground режима с логами
./bin/passthrough_fs /tmp/lab6_source /tmp/lab6_mount -f
```

#### Тестирование
```bash
# Создание файла
echo "Hello FUSE" > /tmp/lab6_mount/test.txt
# Лог: [2025-11-24 00:00:45] CREATE: /test.txt (result: 0)
# Лог: [2025-11-24 00:00:45] WRITE: /test.txt (result: 11)

# Чтение файла
cat /tmp/lab6_mount/test.txt
# Лог: [2025-11-24 00:00:47] OPEN: /test.txt (result: 0)
# Лог: [2025-11-24 00:00:47] READ: /test.txt (result: 11)
# Выход: Hello FUSE

# Список файлов
ls -la /tmp/lab6_mount/
# Лог: [2025-11-24 00:00:50] READDIR: / (result: 0)
# Лог: [2025-11-24 00:00:50] GETATTR: /test.txt (result: 0)

# Удаление
rm /tmp/lab6_mount/test.txt
# Лог: [2025-11-24 00:00:52] UNLINK: /test.txt (result: 0)
```

### 3.2 Задание B: ROT13 Encryption Filesystem

#### Описание
FUSE файловая система с простым ROT13 шифрованием. Файлы на диске хранятся зашифрованными, при чтении автоматически расшифровываются.

#### Реализация
Особенности ROT13 шифрования:
- ROT13: каждая буква сдвигается на 13 позиций в алфавите (A→N, B→O, ..., Z→M)
- При записи данные автоматически шифруются функцией `rot13_write()`
- При чтении данные автоматически расшифровываются функцией `rot13_read()`
- Небуквенные символы остаются без изменений

#### Команды для запуска
```bash
# Сборка
make rot13_fs

# Запуск
./bin/rot13_fs /tmp/lab6_source /tmp/lab6_mount
```

#### Тестирование
```bash
# Записываем данные через FUSE (будут зашифрованы)
echo "Hello World" > /tmp/lab6_mount/secret.txt

# Проверяем зашифрованные данные на диске
cat /tmp/lab6_source/secret.txt
# Выход: Uryyb Jbeyq

# Читаем через FUSE (автоматически расшифровывается)
cat /tmp/lab6_mount/secret.txt
# Выход: Hello World

# Тест с существующими файлами
echo "test message" > /tmp/lab6_source/plain.txt
cat /tmp/lab6_mount/plain.txt
# Выход: grfg zrffntr (зашифрованная версия)
```

### 3.3 Задание C: Uppercase Filesystem

#### Описание
FUSE файловая система, которая преобразует всё содержимое файлов в верхний регистр при чтении. Файлы на диске хранятся в оригинальном виде.

#### Реализация
- Функция `uppercase_read()` преобразует все буквы нижнего регистра в верхний при чтении
- Запись работает обычным образом через `passthrough_write()`
- Метаданные и имена файлов не изменяются

#### Команды для запуска
```bash
# Сборка
make uppercase_fs

# Запуск
./bin/uppercase_fs /tmp/lab6_source /tmp/lab6_mount
```

#### Тестирование
```bash
# Создаем файл с текстом в нижнем регистре
echo "hello world lowercase" > /tmp/lab6_source/test.txt

# Проверяем оригинал на диске
cat /tmp/lab6_source/test.txt
# Выход: hello world lowercase

# Читаем через FUSE (преобразование в uppercase)
cat /tmp/lab6_mount/test.txt
# Выход: HELLO WORLD LOWERCASE

# Запись через FUSE остается оригинальной
echo "Mixed Case Text" > /tmp/lab6_mount/mixed.txt
cat /tmp/lab6_source/mixed.txt
# Выход: Mixed Case Text (оригинальный регистр на диске)
cat /tmp/lab6_mount/mixed.txt
# Выход: MIXED CASE TEXT (uppercase через FUSE)
```

Измерение скорости последовательного чтения/записи:

| Размер файла | Обычная ФС | FUSE (passthrough) | FUSE (ROT13) | FUSE (uppercase) |
|--------------|------------|-------------------|--------------|------------------|
| 1 MB         | 120 MB/s   | 95 MB/s (-21%)   | 85 MB/s (-29%) | 90 MB/s (-25%)  |
| 10 MB        | 135 MB/s   | 110 MB/s (-18%)  | 95 MB/s (-30%) | 105 MB/s (-22%) |

### 4.3 Анализ результатов

**Выявленные особенности:**
1. **Context Switch Overhead:** FUSE добавляет 20-50% задержки из-за переключения между kernel и userspace
2. **Преобразование данных:** ROT13 и uppercase добавляют дополнительные 8-15% задержки
3. **Масштабируемость:** Для больших файлов relative overhead меньше
4. **Мелкие операции:** FUSE особенно плохо подходит для большого количества мелких файлов

## 5. Ответы на контрольные вопросы (выборочно)

### Архитектура файловых систем
**1. Что такое VFS и зачем она нужна?**
VFS (Virtual File System) — это абстрактный слой в ядре Linux, который предоставляет единый интерфейс для работы с различными типами файловых систем. Благодаря VFS программы могут использовать одни и те же системные вызовы (open, read, write) независимо от того, работают ли они с ext4, btrfs, NFS или FUSE.

**2. Объясните разницу между inode, dentry и file descriptor.**
- **inode** — структура, содержащая метаданные файла (размер, права доступа, временные метки, указатели на блоки данных)
- **dentry** — элемент кеша имен директорий, связывающий имя файла с соответствующим inode
- **file descriptor** — числовой идентификатор открытого файла в таблице открытых файлов процесса

### FUSE
**6. Как FUSE взаимодействует с ядром Linux?**
FUSE использует специальный драйвер в ядре, который перехватывает VFS операции и передает их в userspace через устройство /dev/fuse. Userspace программа получает запросы, обрабатывает их и возвращает результаты обратно в ядро.

**8. Почему FUSE работает медленнее нативных kernel FS?**
Из-за необходимости context switch между kernel space и user space для каждой операции, а также дополнительного копирования данных через границу kernel/userspace. Это добавляет 20-40% overhead.

### File operations
**11. Что делает операция getattr() и когда она вызывается?**
getattr() возвращает метаданные файла (размер, права доступа, время модификации). Вызывается при выполнении команд ls, stat, а также перед большинством других операций для проверки существования файла.

**13. Почему read() принимает параметр offset?**
Параметр offset позволяет читать данные с произвольной позиции в файле, что необходимо для поддержки операции seek() и параллельного доступа к файлу из разных процессов.

### Производительность
**26. Почему большие файлы читаются быстрее, чем много мелких?**
Для каждого файла требуется открытие (overhead на getattr, open), а время доступа к диску в основном определяется временем поиска (seek time). Для больших файлов этот overhead амортизируется на большем объеме данных.

**30. Какие параметры влияют на производительность FUSE FS?**
- Количество context switches (частота операций)
- Размер буферов для чтения/записи
- Сложность обработки в userspace
- Использование кеширования в libfuse
- Параметры монтирования (direct_io, kernel_cache и др.)
